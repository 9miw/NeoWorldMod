# โหมดเกิดมอนสเตอร์แต่ละเวฟ

เพิ่มเวฟโดยเลือกแท็บ Server Clone และชื่อโคลนเต็ม (มีช่องว่างได้) เวฟใหม่เริ่มด้วย NPC หนึ่งตัวในโหมด round_robin ตั้งจำนวนแยกโดยใช้หมายเลขเวฟที่เริ่มจาก 1 เวฟที่บันทึกอยู่คงค่าเดิม

```mcfunction
/neoworld dungeon set dung01 wave add 1 Cave Zombie
/neoworld dungeon set dung01 wave edit 1 spawn each 5
/neoworld dungeon set dung01 wave edit 1 spawn random 20
/neoworld dungeon set dung01 wave edit 1 spawn round_robin 20
/neoworld dungeon info dung01
/neoworld dungeon validate dung01
/neoworld dungeon enable dung01
```

- `each`: จำนวนต่อมาร์กเกอร์ ถ้ามี `mob_spawn_1` สี่จุดและจำนวน 5 จะเกิด NPC 20 ตัว
- `random`: จำนวนรวม NPC แต่ละตัวสุ่มมาร์กเกอร์แยกกัน บางจุดอาจไม่มี NPC ถ้ามีสี่จุดและจำนวน 20 ก็ยังเกิดรวม 20 ตัว
- `round_robin`: กระจายจำนวนรวมแบบเดิม วนตามมาร์กเกอร์ทั้งหมด

NPC ทั้งหมดเกิดในขั้นตอนเริ่มเวฟเดียวกัน ไม่ใช่แบ่งชุดตามเวลา โคลน CustomNPCs และแอตทริบิวต์ที่ตั้งไว้ไม่เปลี่ยน มาร์กเกอร์หลายจุดต้องอยู่ต่างตำแหน่ง มาร์กเกอร์เหมือนกันที่ซ้อนตำแหน่งยังถูกรวมเป็นจุดเดียว NPC หลายตัวที่จุดเดียวใช้ออฟเซ็ตเล็กน้อยตามเดิม

คำสั่งรับจำนวน 1..1024 โหมด each/random จำกัดผลรวมไม่เกิน 1024 NPC ด้วย โดยตรวจตอน validate และตอนเกิดจริง ควรใช้จำนวนน้อยกว่านี้มากตามกำลังเซิร์ฟเวอร์ นิยาม round-robin เก่าคงจำนวนและพฤติกรรมเดิม แม้เกินขีดจำกัดคำสั่งใหม่นี้

ฟิลด์ NBT เสริม `spawnMode` เก็บร่วมกับ cloneTab, cloneName และ count ใน SavedData ดันเจี้ยนของ Overworld หากไม่มีหรือไม่รู้จักโหมดจะใช้ round_robin การเปลี่ยนค่าตั้งนิยามกลับเป็น DRAFT และทำเครื่องหมาย SavedData ว่าต้องบันทึก ไม่ต้องเปลี่ยนสคีมาฐานข้อมูลหรือเครือข่าย

การตรวจสอบ: compileJava และ dungeonBrowserRegressionTest ครอบคลุมความหมายจำนวนต่อจุดและจำนวนรวม การสุ่มที่ให้ผลแน่นอน จุดเดียว/ไม่มีจุด ขีดจำกัดรวม การบันทึกและโหลดกลับ และค่าเริ่มต้นของ NBT เก่า การเกิด NPC จริงยังต้องตรวจคุณภาพในเกม
