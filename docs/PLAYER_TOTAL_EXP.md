# EXP สะสมของผู้เล่น

## นโยบายที่ผู้ใช้อนุมัติ

- `exp` ยังเป็น EXP คงเหลือสำหรับเลื่อนระดับ ใช้สูตรเดิม เลเวลสูงสุด 100
- `total_exp` เป็นยอด EXP ที่ได้รับสะสม เซิร์ฟเวอร์ยังไม่เคยเปิด จึงไม่ต้องเก็บวันเริ่มนับหรือคำนวณย้อนหลัง
- เพิ่มยอดหนึ่งครั้งต่อการรับ EXP จากการเล่นผ่าน `PlayerLevelManager.addExp` รวมไอเทม NeoWorld EXP คำสั่งแอดมิน `addexp` ผ่าน `addAdminExp` เพิ่มเลเวล/EXP ปัจจุบันและยอดสะสมด้วยตามนโยบายล่าสุด
- EXP ที่ใช้เลื่อนระดับไม่ถูกหักออกจากยอดสะสม รวมถึง EXP ส่วนเกินที่ทำให้ขึ้นถึงเลเวล 100
- เลเวล 100 ยังสะสมยอดต่อได้ แต่เลเวลคง 100 และ `exp` คง 0
- การตั้งเลเวล/ล้าง EXP ปัจจุบันไม่เปลี่ยนยอดสะสม ไม่มีคำสั่งรีเซ็ตยอดสะสมในงานนี้
- ค่า 0/ติดลบไม่ถูกนับ ยอดสะสมอิ่มตัวที่ `Long.MAX_VALUE` โดยไม่วนเป็นค่าติดลบ
- คำสั่ง `removeexp` ลด EXP ปัจจุบันและถอยเลเวลตามสูตร พร้อมลดยอดสะสมด้วยจำนวนที่ระบุ โดยแต่ละส่วนไม่ต่ำกว่า 0 และเลเวลไม่ต่ำกว่า 1
- ข้อมูลยังอยู่ใน `PLAYER_DATA` Attachment ที่ serialize และ `copyOnDeath` ตามเดิม

## Schema และ API

ข้อมูลอยู่ในไฟล์ `<world>/playerdata/<uuid>.dat` ใต้ `neoforge:attachments` → `neoworld:player_data`

| ฟิลด์ | ชนิด | API | ความหมาย |
|---|---|---|---|
| `total_exp` | long >= 0 | `PlayerData.getTotalExp()` | ยอดรับ EXP ตั้งแต่เริ่มนับ |

ออนไลน์ใช้ `player.getData(ModAttachments.PLAYER_DATA).getTotalExp()` ออฟไลน์อ่าน CompoundTag ของ Attachment แล้วใช้ `PlayerData.CODEC.parse(NbtOps.INSTANCE, tag).getOrThrow().getTotalExp()` ได้โดยไม่สร้าง entity ไม่ให้รางวัล และไม่เขียนไฟล์เซฟ

`PlayerLevelManager.applyExp(PlayerData, long)` เป็นแกนคำนวณเดียวกับเส้นทางให้รางวัลจริง คืนจำนวนเลเวลที่ขึ้น การเรียกเมธอดนี้ซ้ำด้วยจำนวนเดิมถือเป็นการให้รางวัลใหม่ ไม่ใช่การโหลดข้อมูล เส้นทางในเกมใช้ `addExp(ServerPlayer, long)` สำหรับการเล่น หรือ `addAdminExp(ServerPlayer, long)` สำหรับคำสั่งแอดมิน เพื่อให้เอฟเฟกต์และซิงค์ตามเดิม การขึ้นหลายขั้นในหนึ่ง grant เฉลิมฉลองครั้งเดียวที่เลเวลสุดท้าย

## ผู้เล่นเก่าและ save/load

เซฟที่ไม่มี `total_exp` อ่านเป็น `0` โดยไม่อนุมานยอดจากเลเวลหรือ EXP คงเหลือ

ไม่มี timestamp หรือการเริ่มนับวันที่ตอนล็อกอิน ข้อมูลถูกเซฟตามวงจรผู้เล่นปกติ ไม่สแกนหรือเขียนเซฟออฟไลน์ย้อนหลัง หากเซฟทดสอบจากรุ่นก่อนมีฟิลด์วันเริ่มนับ ระบบจะละทิ้งฟิลด์นั้นเมื่อเซฟใหม่โดยรักษายอด EXP

Save/load รักษายอดและไม่เรียกเส้นทางให้รางวัล จึงไม่นับซ้ำ ค่าติดลบหรือฟิลด์ชนิดผิดถูกปฏิเสธโดย codec

## คำสั่งเพิ่ม/ลด EXP

- `/neow level admin addexp <amount> [player]` เพิ่ม EXP และยอดสะสม ขึ้นเลเวลตามปกติ
- `/neow level admin removeexp <amount> [player]` ลด EXP และยอดสะสม ถอยเลเวลเมื่อข้ามขั้น
- จำนวนเป็นจำนวนเต็มบวก ไม่ระบุผู้เล่นจะใช้กับตนเอง; จาก console ต้องระบุผู้เล่นออนไลน์
- สิทธิ์ลดคือ `neoworld.command.level.removeexp` โดยค่าเริ่มต้นต้อง OP 2 เช่นเดียวกับคำสั่งเพิ่ม

การลดอ้างอิงเลเวลกับ EXP ปัจจุบัน ไม่คำนวณเลเวลใหม่จาก total_exp เพราะคำสั่งตั้งเลเวลอาจทำให้สองค่านี้ต่างกัน เช่น 3/118 EXP ลด 200 → 2/200 EXP และยอดสะสมลด 200

เลเวล 100 มี EXP ปัจจุบัน 0 ดังนั้นลด 1 → เลเวล 99 พร้อม EXP 98,502 แม้ยอดสะสมมีส่วนเกินหลังเลเวลตัน ส่วนเกินนั้นเป็นยอดสะสม ไม่ใช่หลอด EXP สำรอง คำสั่งลดไม่เล่นเอฟเฟกต์ขึ้นเลเวล แต่ซิงค์สถานะใหม่และปล่อยให้ระบบตรวจเกราะจัดการข้อจำกัดตามเลเวลใหม่

## เชื่อมหน้าอันดับ

หน้าอันดับแสดง `Entry.totalExp()` ในช่อง EXP รวม ทั้งข้อมูลออนไลน์และออฟไลน์ ส่วน `Entry.exp()` ยังคงเป็น EXP ปัจจุบันสำหรับจัดอันดับเมื่อเลเวลเท่ากัน เกณฑ์เรียงยังเป็นเลเวลก่อน แล้ว EXP ปัจจุบัน แล้ว UUID การแสดงชื่อผู้เล่นรักษาทั้งสองค่า

RankingDataPayload ส่ง totalExp แยกจาก exp; protocol เพิ่มจาก 36 เป็น 37 จึงต้องอัปเดตเซิร์ฟเวอร์และไคลเอนต์พร้อมกัน ไม่มีการเติม EXP แอดมินที่เคยถูกยกเว้นย้อนหลัง เพราะไม่มีข้อมูลแหล่งที่มาของยอดเก่า เซิร์ฟเวอร์ยังไม่เปิดใช้งานจริง

## Verification

`playerExperienceRegressionTest` ทดสอบแยกจาก regression sources ของงานอื่น ด้วย source-file mode บน Java 21 ใช้ codec/NBT และแกนคำนวณจริง ครอบคลุมเลเวลขึ้นหลายขั้น เลเวลตัน reset/set level overflow legacy migration และ compressed offline save

ยังต้องตรวจในเกมเรื่องล็อกอิน เกิดใหม่ และการแสดง EXP บนหน้าอันดับหลังอีกแชทเชื่อม API
