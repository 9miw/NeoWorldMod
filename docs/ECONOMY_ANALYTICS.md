# ระบบข้อมูลประเมินสมดุลเศรษฐกิจ

ระบบนี้เก็บข้อมูลเพื่อวิเคราะห์ ไม่ปรับราคา อัตราดรอป หรือยอดเงินผู้เล่น และไม่เพิ่ม GUI

## การนำ Gold ออกจากระบบ (2 พฤศจิกายน 2026)

สกุลเงินใช้งานเหลือ Silver/Diamond เท่านั้น ยอด Gold เดิมยังเก็บในฟิลด์เซฟและฐานข้อมูลสำหรับข้อมูลเก่า แต่ไม่ส่งไป client ไม่แสดงบนหน้าจอ และไม่มี API เพิ่ม/หัก/ตั้งยอด ไม่แปลงยอดเก่าเป็น Silver ประวัติธุรกรรมเก่าคงสกุลเดิมไว้ในข้อมูลดิบ

Migration 17 ย้ายข้อเสนอร้าน Gold ที่ยังใช้งานไปเป็น Silver โดยคงตัวเลขราคา พร้อมเก็บประวัติการย้าย หากเกิดราคาวนกำไรหลังรวมสกุล migration จะหยุดก่อนเปลี่ยนข้อมูลและแจ้งคู่รายการที่ต้องตรวจ รายการ Gold PENDING เก่าถูกแยกเป็น NEEDS_REVIEW ไม่กู้คืนด้วย Silver

ตีบวกใช้ Silver ทั้ง server และ UI และย้ายคีย์ config เก่าไป silverForLevel โดยคงตัวเลขเดิม หากมีคีย์ Silver ตั้งไว้แล้วจะใช้ค่าที่ตั้งใหม่ FML จัดการสำรอง/บันทึกไฟล์ตามปกติ

นำ registry ของ gold_coin ออก จึงไม่รองรับไอเทมเหรียญ Gold เก่าเมื่อโหลดโลก ไม่ remap เป็น Silver โปรโตคอลรุ่น 42 ต้องอัปเดต client/server พร้อมกัน การแก้ครั้งนี้ไม่ติดตั้งขึ้นเซิร์ฟเวอร์จริง

## ใช้งาน

- `/economyreport status` แสดงจำนวนงานรอบันทึกและจำนวนที่ตกหล่นจากคิวเต็มในรอบเปิดเซิร์ฟเวอร์นี้
- `/economyreport export` สร้าง CSV ย้อนหลัง 28 วัน
- `/economyreport export 14` เลือกช่วงย้อนหลัง 1–365 วัน
- คำสั่งใช้สิทธิ์ระดับ 2; สร้างรายงานครั้งละหนึ่งงาน เบื้องหลังเซิร์ฟเวอร์
- ผลลัพธ์อยู่ `config/neoworld/reports/<เวลา UTC>-<UUID>/` พร้อม README อธิบายข้อจำกัด

ตัวมอดจะเริ่มเก็บข้อมูลเมื่อมีการติดตั้งรุ่นนี้และเปิดเซิร์ฟเวอร์ ไม่สร้างข้อมูลย้อนหลังแทนสิ่งที่ไม่เคยบันทึก

## ข้อมูลและจุดเชื่อมต่อ

Migration 10 เพิ่มตารางตาม table-prefix ที่ตั้งไว้ โดยใช้ฐานข้อมูลและ connection pool เดิม:

| ตาราง | หน้าที่ |
| --- | --- |
| `economy_events` | ประวัติ wallet, เวลาเล่น, ตลาด, การตั้งราคา/ค่าธรรมเนียม, การออกเหรียญรางวัล และเริ่ม/หยุดการเก็บข้อมูล |
| `economy_balances` | ยอด wallet ล่าสุดที่พบ พร้อมเวลา เลเวล และสถานะแอดมิน |
| `economy_daily_balances` | ยอดรายวัน แยกวันด้วยเขตเวลา Asia/Bangkok และเก็บเวลาที่ตรวจพบยอดจริงไว้ |

ยอดจริงยังอยู่ใน `PlayerData` Attachment และไฟล์ผู้เล่น ไม่อ่านยอดจากตารางวิเคราะห์กลับไปเขียนทับผู้เล่น

การเปลี่ยน wallet เก็บ UUID, เวลาจริงแบบ epoch milliseconds, เลเวล, สกุลเงิน, ยอดก่อน/หลัง, ผลต่าง, แหล่ง และรหัสเชื่อมรายการ ครอบคลุมจุดที่มีอยู่ในโค้ดปัจจุบัน:

- ร้าน NPC: รับซื้อจากผู้เล่นเป็น SOURCE; ผู้เล่นซื้อจากระบบเป็น SINK
- ตลาดผู้เล่น: ค่าลงขายเป็น SINK; ซื้อและรับรายได้เป็น TRANSFER; ภาษีเป็น SINK แยก ณ ตอนขายสำเร็จ
- เทรดตรงระหว่างผู้เล่นเป็น TRANSFER โดยใช้รหัสห้องเทรดเชื่อมสองฝ่าย
- ตีบวกและการใช้เงินผ่าน CustomNPCs เป็น SINK
- คำสั่งเพิ่ม/หัก/ตั้งเงินเป็น ADMIN พร้อมชื่อผู้สั่ง และบันทึกการเปลี่ยนมูลค่าเหรียญด้วยคำสั่ง setcoin แยกต่างหาก
- แปลงเหรียญจากพื้น/กระเป๋าเป็น UNKNOWN เพราะยังพิสูจน์แหล่งเหรียญเดิมไม่ได้
- ยอดที่เปลี่ยนผ่านช่องทางอื่นจะตรวจผลต่างจากการสังเกตครั้งก่อนและบันทึกเป็น UNKNOWN

วัดผลต่างก่อนและหลังการทำงานของแต่ละบริการ ดังนั้นรายการที่หักเงินแล้วคืนจนยอดเท่าเดิมไม่สร้างรายได้หรือรายจ่ายปลอม การเปลี่ยนหลายครั้งที่หักล้างกันภายในช่องทางที่ยังไม่มีจุดเชื่อมเฉพาะอาจมองไม่เห็นจากการตรวจผลต่าง

ร้าน NPC ใช้ `shop_transactions` เดิมสำหรับ snapshot item/components และจำนวนเงิน ไม่ทำสำเนา NBT ซ้ำใน wallet event รหัส correlation ของ wallet ตรงกับ transaction ID เดิม และเพิ่ม item ID, จำนวน, ราคาต่อชิ้น และทิศทางไว้ให้วิเคราะห์ง่าย

ตลาดเก็บสำเนาประวัติลงขาย/ขายสำเร็จ/ยกเลิก/หมดอายุพร้อม item/components, จำนวน และเวลาจริง ใน transaction เดียวกับการดำเนินการเดิม ผู้เล่นลบประวัติรายการรับเงินแล้วได้ตามเดิม แต่ลบประวัติวิเคราะห์นี้ไม่ได้ การซื้อบางส่วนบันทึกเฉพาะจำนวนที่ขายจริง เวลาขายออกนับจากการลงขายครั้งแรกถึงแต่ละรายการขาย; รายการเก่าที่ไม่มีเวลาเริ่มจริงเว้นว่าง

เมื่อเปิดเซิร์ฟเวอร์ เก็บ baseline ข้อเสนอร้านปัจจุบันและกิจกรรมรายวัน/รายเดือน/ออนไลน์ การเพิ่ม/ลบข้อเสนอและเปลี่ยนค่าธรรมเนียมผ่าน repository จะมีประวัติใน transaction เดียวกัน การแก้ฐานข้อมูลนอกมอดไม่ผ่านจุดนี้และจะเห็นได้จาก baseline ครั้งถัดไปเท่านั้น

กิจกรรมที่แจกเหรียญบันทึก COIN_ISSUED แยกจาก wallet ส่วนดันเจียนบันทึกเมื่อสร้างเหรียญในกล่องรางวัลส่วนตัว ซึ่งผู้เล่นอาจยังไม่หยิบ ไม่เอารายการออกเหรียญไปบวกกับการแปลงเหรียญเข้ากระเป๋าซ้ำอีก ไม่ติด component ติดตามแหล่งบนตัวเหรียญ และยังไม่ตามแหล่งเหรียญจากเควสต์/สคริปต์/ปลั๊กอินภายนอกหรือมอนสเตอร์

## เวลาเล่นและ snapshot

นำช่วงเวลาและเกณฑ์ AFK จากระบบ Activity เดิมมาใช้ โดยรวมเวลาเป็นช่วง ACTIVE / AFK / EXCLUDED แยกเลเวลและสถานะแอดมิน; EXCLUDED คือเสียชีวิตหรือ spectator ช่วงเวลาระหว่างการตรวจนับจำกัดสูงสุด 5 วินาทีตามระบบเดิม เพื่อลดผลจากการหยุดค้างของเซิร์ฟเวอร์ จึงไม่ใช่การรับรองว่าผู้เล่นกำลังเล่นจริง

บันทึกเวลาเป็นกลุ่มไม่เกินประมาณหนึ่งนาที และแบ่งเมื่อเลเวล/สถานะเปลี่ยน วันที่เปลี่ยนอาจคลาดเคลื่อนตามช่วงตรวจประมาณหนึ่งวินาที ขอบรายงานอาจรวมเวลานอกช่วงได้ไม่เกินประมาณหนึ่งนาที

สังเกตยอดเมื่อเข้า ออก ทุกประมาณหนึ่งนาที และก่อนส่งออกรายงาน วันใหม่คัดลอกยอดล่าสุดของผู้เล่นที่เคยพบมาเป็น snapshot ของวันนั้นด้วย โดยคง `observed_at` เดิมของคนออฟไลน์ ไม่อ้างว่าเป็นยอดที่เพิ่งตรวจจริง ไม่อ่านไฟล์ผู้เล่นออฟไลน์เพื่อทำ backfill

## รายงาน

| ไฟล์ | เนื้อหา |
| --- | --- |
| `summary.csv` | เงินสุทธิ SOURCE/SINK ที่ทราบแหล่ง, TRANSFER/UNKNOWN แยก, ภาษี, เหรียญที่ออก และเวลาแต่ละสถานะ |
| `npc_trades.csv` | รายการ NPC พร้อม item ID จำนวน ราคาต่อหน่วย ยอดรวม และ audit ID สำหรับตาม components |
| `npc_transactions.csv` | ประวัติ NPC เดิม พร้อม NBT แบบ Base64 รวมข้อมูลก่อนติดตั้งที่ยังมีอยู่ |
| `npc_sources.csv` | รายรับจากแต่ละข้อเสนอ และสัดส่วนเทียบเงินที่ร้าน NPC สร้างในสกุลเดียวกัน |
| `market_sales.csv` | ราคาซื้อขายจริง จำนวน ภาษี และเวลาขายออก |
| `player_income.csv` | รายรับ wallet ที่เป็นบวก และรายได้จากระบบที่ยืนยันแหล่งได้ ต่อชั่วโมง ACTIVE แยกสกุลเงิน |
| `income_silver/diamond.csv` | median, p90, p95 ของรายรับต่อชั่วโมง และสถิติรายได้จากระบบที่ทราบแหล่ง |
| `wealth.csv` | จำนวนผู้เล่นที่เคยพบ ยอดรวม median p90 สัดส่วนเงินของกลุ่มบน 10% และจำนวนยอดเก่ากว่า 24 ชั่วโมง |
| `npc_affordability.csv` | สัดส่วนผู้เล่นที่มี wallet พอซื้อหนึ่งชิ้น และชั่วโมงโดยประมาณจาก median รายได้ระบบที่ทราบแหล่ง |
| `balances_latest.csv`, `balances_daily.csv` | ยอด wallet ล่าสุด/รายวันพร้อมเวลาที่พบจริง |
| `market_pending_balances.csv` | เงินตลาดที่ยังไม่ได้กดรับ ณ ตอนส่งออก แยกจาก wallet |
| `events.csv` | ประวัติทั้งหมด รวมรายละเอียด JSON และข้อมูลแอดมินสำหรับตรวจสอบ |

ไม่รวมแอดมิน/creative/spectator และ ADMIN flow ในสรุปหลัก แต่ยังมีข้อมูลในไฟล์ดิบ ธุรกรรมตลาดที่ผู้ซื้อหรือผู้ขายออนไลน์เป็นแอดมินจะติดธงด้วย การติดธงนี้อิงสถานะขณะทำรายการ ไม่ติดตามที่มาของเงินหลังถูกส่งต่อให้ผู้เล่นอื่น ประวัติ NPC เก่าที่ไม่มีธงแอดมินไม่ถูกนำมารวมในสรุปใหม่

คำว่า **รายรับ wallet** รวมเงินโอนและการแปลงเหรียญ จึงไม่ใช่กำไรหรือเงินสร้างใหม่ ส่วน **รายได้จากระบบที่ทราบแหล่ง** ไม่รวม UNKNOWN และเหรียญรางวัลที่ยังไม่แปลงเข้ากระเป๋า ชั่วโมงซื้อของเป็นเพียงค่าประมาณจากแหล่งที่ทราบ ถ้า median เป็นศูนย์/ไม่มีข้อมูลจะเว้นว่าง Median ใช้ค่าเฉลี่ยสองค่ากลางเมื่อจำนวนผู้เล่นเป็นเลขคู่; p90/p95 ใช้ nearest rank

ความมั่งคั่งและกำลังซื้อในรายงานหลักวัด wallet ของผู้เล่นที่เคยพบตั้งแต่ติดตั้ง ยังไม่รวมเหรียญในไอเทม เงินค้างรับตลาด หรือผู้เล่นออฟไลน์ที่ไม่เคยเข้า ข้อมูลยอดซื้อขายเป็นสัญญาณสินค้าล้น/ขาด ไม่ใช่จำนวนสินค้าทั้งเซิร์ฟเวอร์

## ความทนทานและผลต่อเซิร์ฟเวอร์

งาน wallet/presence/snapshot เข้าคิวจำกัด 16,384 งาน และเขียนเบื้องหลังเป็น transaction ชุดละไม่เกิน 256 งาน ใช้ event ID เดิมเมื่อ retry เพื่อไม่เขียนซ้ำ ถ้าเขียนล้มเหลวจะเก็บงานไว้ลองใหม่และแจ้ง error ไม่เกินหนึ่งครั้งต่อนาที ถ้าคิวเต็มจะนับงานที่ตกหล่นและแจ้ง error ห้ามตีความช่วงนั้นว่าข้อมูลครบ

การปิดตามปกติพยายามระบายคิวก่อนปิดฐานข้อมูลสูงสุด 10 วินาที การ crash/kill อาจทำงานที่อยู่ในหน่วยความจำหาย คิวนี้ไม่ใช่ durable journal ไฟล์ README ของรายงานแสดง pending/lost ปัจจุบัน และ RUN_START/RUN_STOP ช่วยระบุช่วงเปิดเซิร์ฟเวอร์ที่ไม่มีการปิดตามปกติ ควรตรวจ server log ร่วมด้วย

ฐานข้อมูลกับ Attachment อยู่คนละระบบเซฟ จึงไม่รับประกัน atomicity ข้ามไฟล์ผู้เล่นกับฐานข้อมูลเมื่อเซิร์ฟเวอร์ crash ระบบวิเคราะห์ไม่เปลี่ยนวิธีเซฟยอดเงินเดิม รายงานส่งออกอาจตามข้อมูลที่ยังรอคิวอยู่เล็กน้อย ไฟล์ถูกสร้างเบื้องหลังและคำสั่งแจ้งสำเร็จเมื่อเขียนครบเท่านั้น

ยังไม่มีการล้างประวัติอัตโนมัติ ควรเฝ้าดูขนาดฐานข้อมูลเมื่อเก็บต่อเนื่องและกำหนด retention ภายหลังตามปริมาณจริง

## การตรวจสอบ

ทดสอบด้วยฐานข้อมูล H2 แยกจากข้อมูลผู้เล่น รวม H2 MariaDB compatibility mode: สร้างใหม่, อัปเกรดจาก v9, retry migration ที่มีบางตารางแล้ว, รักษาข้อมูลเดิม, rollback, event retry ไม่ซ้ำ, snapshot ออฟไลน์ไม่ปลอมเวลา, ประวัติวันเก่าไม่ถูกเขียนทับ และส่งออก CLOB เป็น JSON จริง

MariaDB compatibility mode ไม่ใช่การทดสอบ MariaDB server จริง ต้องตรวจการทำงานในเกมและบนฐานข้อมูลเป้าหมายก่อนอ้างว่าผ่าน runtime จริง
