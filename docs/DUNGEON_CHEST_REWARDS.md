# รางวัลที่บันทึกจากหีบ

1. วางหีบธรรมดาหรือหีบกับดัก แบบเดี่ยวหรือคู่ แล้วจัดไอเทมจริงไว้
2. เล็งหีบจากระยะไม่เกินแปดบล็อก แล้วใช้คำสั่ง:

```mcfunction
/neoworld dungeon admin loot save slime_reward
/neoworld dungeon admin set silme reward slime_reward
/neoworld dungeon admin validate silme
/neoworld dungeon admin enable silme
```

ใช้ได้ทั้งชื่อสั้นและ ID เต็ม เช่น `neoworld:dungeon/rewards/slime_reward` ชื่อต้องไม่ซ้ำ การบันทึกชื่อที่มีอยู่ไม่เขียนทับ หากต้องการเปลี่ยนชุดรางวัลให้บันทึกชื่อใหม่ การกด Tab ใน `set ... reward` จะแนะนำชื่อที่บันทึกไว้ ID Loot Table แบบระบุเนมสเปซยังใช้ได้เหมือนเดิม หาก ID ตรงกันจะใช้พรีเซ็ตที่บันทึกก่อน

คำสั่งคัดลอก NBT ของ ItemStack แบบอ้างอิงรีจิสทรีครบถ้วน ทั้งจำนวน ชื่อกำหนดเอง เอนชานต์ custom data และ Data Components ของม็อดที่ลงทะเบียนไว้ ไม่ดึงไอเทมหรือล้างหีบต้นทาง ปฏิเสธหีบว่าง จำนวนสแต็กเกินกำหนด จำนวนช่องเกิน 54 และข้อมูลเกิน 64 KiB หากหีบยังไม่ได้สุ่ม Loot Table ให้เปิดและจัดไอเทมก่อนบันทึก

## โอกาสและจำนวน

```mcfunction
/neoworld dungeon admin loot chance slime_reward 1 25
/neoworld dungeon admin loot amount slime_reward 1 2 5
/neoworld dungeon admin validate silme
/neoworld dungeon admin enable silme
```

หมายเลขช่องในหีบที่บันทึกเริ่มจาก 1 เรียงซ้ายไปขวาและบนลงล่าง รวมช่องว่าง ตัวอย่างนี้ให้ช่อง 1 มีโอกาส 25% ที่จะได้รับไอเทมจำนวนสุ่มเท่า ๆ กันในช่วง 2..5 เปอร์เซ็นต์รับทศนิยมตั้งแต่ 0..100 ค่า 0 ปิดช่องนั้น ช่วงจำนวนรวมปลายทั้งสอง มีขั้นต่ำ 1 และต้องไม่เกินขนาดสแต็กสูงสุดของไอเทมจริง ปฏิเสธช่องว่าง ช่องที่ไม่มีอยู่ และช่วงกลับด้าน ค่าเริ่มต้นคือโอกาส 100% และจำนวนเดิม

แต่ละคำสั่งคงการตั้งค่าอีกส่วนไว้ ชื่อที่มีเนมสเปซก็ใช้ได้ ห้ามเปลี่ยนระหว่างดันเจี้ยนที่เชื่อมกำลังใช้งาน กรณีอื่นจะตั้งนิยามที่เชื่อมกลับเป็น DRAFT กฎบันทึกไปกับสแนปช็อต ผู้เล่นแต่ละคนสุ่มแยกกันตอนสร้างคลังส่วนตัวในการเปิดครั้งแรกเท่านั้น ไม่สุ่มเมื่อเปิดซ้ำ หากสุ่มไม่ผ่านจะเหลือช่องว่าง คอมโพเนนต์ไอเทมคัดลอกตามเดิม
พรีวิวในเบราว์เซอร์ละช่องโอกาสศูนย์ แสดงจำนวนสูงสุด และระบุรางวัลที่แปรผันว่าเป็นค่าประมาณ กฎที่บันทึกผิดรูปแบบจะปิดช่องนั้น แทนการเปลี่ยนเป็นดรอปแน่นอนโดยไม่แจ้ง พรีเซ็ตเก่ายังคงรางวัลจำนวนคงที่

การทดสอบรีเกรสชันครอบคลุมขอบเขตเปอร์เซ็นต์ ความถี่แบบกำหนด seed ขอบเขตจำนวนแบบรวมปลาย ค่าผิด กฎที่บันทึก ค่าเริ่มต้นแบบเก่า และการลงทะเบียนคำสั่ง พฤติกรรมเปิดครั้งแรกแยกต่อผู้เล่นยังต้องทดสอบในเกมจริง

พรีเซ็ตเก็บใน SavedData ดันเจี้ยนของ Overworld แยกจากหีบต้นทาง เก็บตำแหน่งช่องเดิมรวมช่องว่าง ผู้เล่นที่มีสิทธิ์แต่ละคนได้รับสำเนา ItemStack แยกในคลังรางวัลส่วนตัวเมื่อเปิดครั้งแรก หีบเดี่ยวใช้สามแถว หีบคู่ใช้หกแถว แคชคอนเทนเนอร์ส่วนตัวเดิมทำให้ปิดแล้วเปิดใหม่ไม่เติมรางวัล ไม่มี EXP หรือเงินอัตโนมัติเพิ่มเติม

เบราว์เซอร์แสดงสแต็กจริงและจำนวนที่บันทึกไว้ เพย์โหลดคอมโพเนนต์ที่ใหญ่มากอาจถูกละจากพรีวิวเพื่อจำกัดขนาดแพ็กเก็ต พร้อมตัวบอกว่าพรีวิวไม่ครบ แต่ไม่ตัดข้อมูลจากรางวัลจริง รูปแบบแพ็กเก็ตไม่เปลี่ยน นิยาม Loot Table เดิมยังโหลดและสุ่มตามปกติ

การตรวจสอบ: compileJava และ dungeonBrowserRegressionTest ครอบคลุมความเป็นเจ้าของ NBT ที่ซีเรียลไลซ์ การคงจำนวนและคอมโพเนนต์ การโหลดใหม่ ชื่อไม่ซ้ำ ข้อจำกัดช่อง การเลือกต้นทาง และรูปแบบคำสั่งที่มีเนมสเปซ การถอดรหัส ItemStack ด้วยรีจิสทรี การเล็งหีบจริง คอมโพเนนต์ม็อด และการรับรางวัลต่อผู้เล่นยังต้องทดสอบในเกม การทดสอบไปกลับของ NBT ดิบที่เก็บไว้ไม่ใช่การทดสอบรันไทม์เกมครบถ้วน
