# NeoWorld Killer & Red-Name System (ระบบบาปสะสมและหัวแดง)

## 1. ภาพรวม
ระบบ Killer ของ NeoWorld เป็นระบบที่ควบคุมและลงโทษการฆ่าผู้เล่น (PK) นอกสนามประลอง เพื่อรักษาสมดุลของโลกเกม โดยใช้กลไก **บาปสะสม (Accumulated Sin)**, **สิทธิ์การป้องกันตัว (Self-Defense)**, **ชื่อสีแดงเหนือหัว (Red Name Tag)** และ **ค่าปรับเมื่อตาย (Death Penalty)**

---

## 2. กติกาและค่าคงที่หลัก

| พารามิเตอร์ | ค่า | คำอธิบาย |
| :--- | :--- | :--- |
| `SIN_PER_KILL` | `100` | แต้มบาปที่ได้รับต่อการฆ่าผู้เล่นปกติ 1 คน |
| `isRed` | `sin > 0` | หากมีแต้มบาปมากกว่า 0 จะมีสถานะเป็น "หัวแดง" |
| `DEFENSE_TICKS` | `1,200` (60 วินาที) | ระยะเวลาสิทธิ์การสวนกลับของผู้ถูกโจมตี |
| `CREDIT_TICKS` | `600` (30 วินาที) | เครดิตการฆ่าจากสิ่งแวดล้อมแก่ผู้เล่นที่โจมตีล่าสุด |
| `DECAY_TICKS` | `12,000` (10 นาที) | ระยะเวลาออนไลน์สะสมเพื่อลดบาป 1 รอบ |
| `DECAY_SIN` | `10` | จำนวนแต้มบาปที่ลดลงต่อรอบ 10 นาที (ไม่ต่ำกว่า 0) |
| ค่าปรับ Silver เมื่อหัวแดงตาย | `5%` สูงสุด `1,000` | ปัดเศษลง (`min(silver / 20, 1000)`), นำออกจากระบบ (Sink) |

## 3. กลไกการทำงานในระบบ

### 3.1 สิทธิ์การป้องกันตัว (Self-Defense)
- เมื่อผู้เล่น A ทำความเสียหายจริงแก่ผู้เล่น B โดยที่ B ไม่ได้เป็นผู้เริ่มโจมตี A ก่อน ผู้เล่น B จะได้รับ **สิทธิ์ป้องกันตัว** ต่อผู้เล่น A เป็นเวลา 60 วินาที
- หาก B สวนกลับทำความเสียหายใส่ A ผู้เล่น A **จะไม่ได้รับสิทธิ์สวนกลับย้อนกลับมา**
- หาก B ฆ่า A ในช่วงเวลานี้ B จะไม่ได้รับแต้มบาป

### 3.2 เครดิตการตายจากสิ่งแวดล้อม (Environmental Kill Credit)
- หากผู้เล่นถูกผู้เล่นอื่นโจมตี แล้วตายจากสภาพแวดล้อม (ตกจากที่สูง, จมน้ำ, ลาวา, มอนสเตอร์) ภายใน 30 วินาทีหลังจากถูกโจมตีล่าสุด ผู้โจมตีล่าสุดจะได้รับเครดิตการฆ่า
- หากการฆ่านั้นไม่เข้าข่ายการป้องกันตัวและเหยื่อไม่ใช่หัวแดง ผู้โจมตีจะได้รับแต้มบาป 100

### 3.3 การตรวจสอบเจ้าของความเสียหาย (Attacker Resolution)
- คำนวณเจ้าของที่แท้จริงจาก Projectile (ลูกธนู, สกิล) และสัตว์เลี้ยงที่เชื่อง (`TamableAnimal`)
- หากระบุเจ้าของไม่ได้ หรือเจ้าของไม่ใช่ผู้เล่น จะไม่นับเป็นการฆ่าโดยผู้เล่น และไม่เดาเจ้าของจากผู้เล่นที่อยู่ใกล้เคียง

### 3.4 การลดบาป (Sin Decay)
- ลดบาป 10 แต้ม ทุกๆ 10 นาที (12,000 ticks) ที่ผู้เล่นคนนั้น **ออนไลน์และอยู่นอกโซนห้าม PvP ของ FTB Chunks**
- เข้าโซนห้าม PvP แล้วหยุดทั้งการลดบาปและเวลาสะสม ออกจากโซนจะนับต่อจากที่ค้างไว้ ไม่รีเซ็ต เซฟ/โหลดแล้วยังคงเวลาค้างเดิม
- ใช้กฎ FTB Chunks รุ่น 2101.1.22 ณ ตำแหน่งผู้เล่นและมิติปัจจุบัน: `ALWAYS` ไม่หยุด, `NEVER` หยุดในเคลมทุกทีม, `PER_TEAM` หยุดเมื่อเจ้าของเคลมไม่อนุญาต PvP พื้นที่ไม่ได้เคลมไม่นับเป็นโซนห้าม PvP จากกฎนี้
- หาก FTB manager ยังไม่พร้อมตอบ ให้พักเวลาลดบาปจนกว่าจะพร้อม ไม่แก้การตั้งค่า FTB หรือสิทธิ์ของทีม
- ออฟไลน์จะไม่นับเวลา
- ผู้เล่นที่ไม่มีบาป (`sin == 0`) จะไม่สะสมเวลาล่วงหน้า

### 3.5 ค่าปรับเมื่อตาย (Death Penalty)
- หากผู้เล่นที่มีสถานะหัวแดง (`sin > 0`) ตายจริงนอกสนามประลอง จะถูกหัก Silver 5% จากกระเป๋า (สูงสุด 1,000 Silver ต่อครั้ง)
- เงินจะถูกนำออกจากระบบ (Sink) ไม่มีการดรอปเป็นไอเทมหรือมอบให้ผู้ฆ่า เพื่อป้องกันการปั๊มเงิน
- ผู้เล่นปกติที่ไม่มีบาป (`sin == 0`) จะไม่เสียเงินเมื่อตาย

### 3.6 ข้อยกเว้นสนามประลอง (PvP Arena Exclusion)
- การต่อสู้และการตายในระบบ PvP Arena (`PvpRoomManager.inArena`) ได้รับการยกเว้นทั้งหมด:
  - ไม่ได้รับแต้มบาปจากการฆ่าในสนาม
  - ผู้เล่นหัวแดงไม่เสีย Silver เมื่อแพ้/ตายในการประลอง
  - การตายที่ถูก cancel โดยระบบจะไม่ถูกนำมาคิดโทษ
  - การโจมตีในสนามไม่สร้างสิทธิ์ป้องกันตัวหรือเครดิตการฆ่าสำหรับโลกปกติ และล้างข้อมูลต่อสู้เดิมของทั้งสองฝ่ายเมื่อมีการโจมตีในสนาม

### 3.7 ลำดับการคิดโทษ
- เก็บสถานะหัวแดงและสิทธิ์ป้องกันตัวขณะเกิดเหตุ แต่ยังไม่หักเงินหรือเพิ่มบาประหว่างส่ง `LivingDeathEvent`
- ที่ปลาย server tick ตรวจสถานะยกเลิกสุดท้ายแล้วจึงคิดโทษครั้งเดียวต่อชีวิตตัวละคร การตายที่ถูกยกเลิกไม่ปิดกั้นการตายจริงครั้งถัดไปใน tick เดียวกัน
- หากเกิดใหม่ก่อนคิวทำงาน ให้คิดโทษจาก Attachment ของตัวละครใหม่หลัง NeoForge คัดลอกข้อมูลแล้ว หากมีผู้เล่นออกเกม ให้ประมวลผลคิวทั้งหมดก่อนบันทึกและนำผู้เล่นออก เพื่อไม่ให้ผู้ฆ่าหลบบาปด้วยการออกเกมทันที
- เปิด `EconomyAnalytics.observe` ก่อนหัก Silver และปิดหลังหัก เพื่อบันทึกส่วนต่างเป็น `killer_death_penalty` / `SINK`

## 4. การแสดงผลและการซิงค์ (Presentation & Network)

1. **ชื่อเหนือหัวผู้เล่น (Head Nametag):**
   - เมื่อผู้เล่นมีสถานะหัวแดง (`sin > 0`), Client จะแสดงผลชื่อของผู้เล่นเป็นสีแดง (`ChatFormatting.RED`)
   - ไม่กระทบสีของยศ (Title) ที่ลอยอยู่ด้านบน และไม่กระทบ Team / Scoreboard เดิม
2. **หน้าโปรไฟล์ตัวละคร (Player Profile GUI):**
   - แสดงชื่อเป็นสีแดงหากเป็นหัวแดง
   - ในแท็บความก้าวหน้า/สถานะ แสดงค่าบาปปัจจุบัน พร้อมข้อความอธิบายว่าลดบาปเฉพาะออนไลน์นอกโซนห้าม PvP
3. **การซิงค์ข้อมูล (Networking):**
   - เซิร์ฟเวอร์ส่ง packet `KillerStatePayload` เมื่อผู้เล่นเข้าเกม, เกิดใหม่, มีการเปลี่ยนแปลงแต้มบาป, และเมื่อมีผู้เล่นอื่นเข้ามาในระยะ tracking (`StartTracking`)
   - ล้างข้อมูล Client เมื่อผู้เล่นหลุดหรือออกจากเซิร์ฟเวอร์ (`ClientConnectionEventHandler`)

## 5. การทดสอบและการรับรอง (Testing & Verification)
- ผ่านการทดสอบอัตโนมัติด้วย Unit & Regression Tests ใน `KillerRegressionTest`:
  1. ค่าปรับเงิน Silver: เศษปัดลง, ค่าเริ่มต้น 5%, แคปที่ 1,000 Silver, ค่าติดลบ/เกิน Long.MAX_VALUE ไม่ overflow
  2. การสวนกลับและเครดิตสิ่งแวดล้อม: สิทธิ์สวนกลับไม่สลับให้ผู้เริ่ม, หมดอายุตามเวลา, การ logout/respawn ล้างสถานะการต่อสู้
  3. ความคงทนและการลดบาป: เซฟลง NBT และโหลดกลับมาได้สมบูรณ์, ลดบาปเมื่อครบ 12,000 ticks, ไม่สะสมเวลาล่วงหน้า
  4. การจำแนกความตาย: ฆ่าคนปกติได้บาป, ฆ่าหัวแดงไม่ได้บาป, สวนกลับไม่ได้บาป, สนามประลองไม่ได้บาป
  5. แคชและการซิงค์ Client: อัปเดต, ตรวจสอบสถานะหัวแดง, ลบ และรีเซ็ตแคชอย่างถูกต้อง
  6. `KillerLifecycleRegressionTest`: แยกสิทธิ์สนามออกจากโลกปกติ, ยกเลิกการตายภายหลัง, ตายจริงซ้ำใน tick เดียวกัน, คิดโทษครั้งเดียว, หักจากกระเป๋าตัวละครใหม่ และตัวติดตามเงินเห็นยอดก่อน/หลังหัก
  7. `KillerSafeZoneRegressionTest`: หยุดที่ขอบรอบลดบาป, เซฟ/โหลดเวลาค้าง, เข้าออกโซนซ้ำ, กลับมานับต่อ และแยก `ALWAYS`/`NEVER`/`PER_TEAM` กับเคลมและพื้นที่นอกเคลม

การทดสอบอัตโนมัติไม่ได้ยืนยันการทำงานในเกมจริง ต้องทดสอบ PvP สองผู้เล่น การออกเกมทันทีหลังฆ่า การเกิดใหม่ และการยกเลิกการตายร่วมกับม็อดอื่นในเกมเพิ่มเติม

## 6. Combat Logout

- เมื่อทำหรือรับความเสียหายจริงจากผู้เล่น จะติดสถานะต่อสู้ทั้งสองฝ่าย 60 วินาทีหลังความเสียหายล่าสุด (1,200 server ticks) การโจมตีตัวเองไม่ติดสถานะ
- ออกเกมระหว่างสถานะนี้จะเก็บ `ServerPlayer` ตัวจริงไว้ในโลกอีก 60 วินาทีหลังออกเกม ตัวละครถูกโจมตีและฆ่าได้ ใช้กระเป๋า เงิน Attachment และระบบตายเดิม ไม่มี NPC หรือกระเป๋าสำเนา
- การถูกตีเพิ่มอาจต่ออายุ combat tag แต่ไม่ยืดอายุของตัวละครที่ออกเกมแล้วเกินกำหนดเดิม
- การออกเกมปกติ, Creative, Spectator และผู้เล่นในห้อง PvP ไม่ค้างตัวละคร ผู้เป็นเจ้าของเซิร์ฟเวอร์ Singleplayer/LAN ออกแล้วปิดโลกตามเดิม
- ปิดเมนู ยกเลิก Trade และคิว/ห้อง PvP ทันทีที่การเชื่อมต่อขาด ช่วงออกเกมไม่นับเป็นเวลาลดบาป และไม่สะสม packet ไปยัง connection ที่ปิดแล้ว
- Actionbar เตือนเวลาที่เหลือและแจ้งเมื่อออกเกมได้ตามปกติ มีข้อความไทย/อังกฤษ
- กลับเข้าเกมก่อนหมดเวลา: ตัวละครค้างยังถูกโจมตีได้ระหว่างยืนยันบัญชีและโหลด configuration จากนั้นบันทึกและนำตัวเก่าออกก่อนโหลดสถานะล่าสุดเข้าเกมเพียงชุดเดียว คงช่วงเสี่ยงที่เหลือและเวลา invulnerability เดิม ไม่ให้เกราะคุ้มกันแรกเข้า 60 ticks ใหม่จากการรีล็อก
- ยังคงตรวจ ban/whitelist และบัญชีซ้ำตามเดิม ยกเว้นการเช็ก slot เต็มเฉพาะบัญชีที่มีตัวค้างของตนอยู่แล้ว ล็อกอินที่แข่งกันระหว่าง configuration ไม่สามารถลงตัวละคร UUID เดียวกันสองตัว
- ตัวละครตายหรือหมดเวลา: ประมวลผลคิว Killer ก่อนเรียก logout/save/remove ปกติเพียงครั้งเดียว หากกลับมาตอนตายให้ใช้สถานะตายและไอเทมหลังตายตามเดิม
- ปิดเซิร์ฟเวอร์: ปิดการเริ่ม retention และบันทึก/นำตัวค้างออกทันที ไม่รอให้ครบเวลา ไม่ทิ้ง entity พิเศษไว้ใน world save

### ผลการตรวจอัตโนมัติ
`CombatLogoutRegressionTest` ตรวจ combat timer สองฝ่าย, arena exclusion, body deadline คงที่, duplicate disconnect, release ครั้งเดียว และข้อมูลกระเป๋าตัวจริง

`CombatLogoutHooksRegressionTest` ตรวจ config ลงทะเบียนและ bytecode contract ของ mixin ทั้ง disconnect, login, configuration, join, closed connection และ field invulnerability กับ Minecraft 1.21.1 / NeoForge 21.1.248 ที่ติดตั้ง การตรวจนี้ไม่ได้เทียบเท่าการเปิดเกมจริง

ผ่าน `compileJava`, `killerRegressionTest`, `playerProfileRegressionTest`, `pvpRegressionTest`, `tradeRegressionTest` และ `regressionTest` โดยไม่มี full build/package

### การตรวจในเกมที่ยังต้องทำ
ใช้ client สองตัวบนเซิร์ฟเวอร์ทดสอบ: ตีผู้เล่นแล้วออกเกม, ฆ่าตัวค้าง, กลับเข้าก่อน/หลังครบ 60 วินาที, reconnect ระหว่างถูกตี, ตรวจไอเทม/เงิน/บาปหลังตาย, ล็อกอินซ้อนบัญชีเดียวกัน, server เต็ม, สนาม PvP และ shutdown ขณะมีตัวค้าง ยังไม่ได้ตรวจ runtime เหล่านี้
