# ระบบกิจกรรม NeoWorld

เปิดจาก Hub หรือ `/neoworld activity` (ใช้ `/neow activity` ได้ด้วย)

## กติกา

- เช็กอินวันละหนึ่งครั้ง กดรับรายวันหรือ “รับทั้งหมด” เพื่อเช็กอิน ไม่ได้เช็กอินเพียงเปิดหน้าจอ
- เช็กอินแล้วเพิ่มวันรายเดือนและสร้างรางวัลรายเดือนให้อัตโนมัติ สูงสุด 28 วันต่อเดือน ขาดวันได้
- รายเดือนมีโบนัสวันที่ 7, 14, 21 และ 28
- ออนไลน์สะสม 15 / 30 / 60 / 120 นาทีต่อวัน ออกจากเกมแล้วกลับมาเล่นต่อได้
- รีเซ็ตเวลา 04:00 Asia/Bangkok รายเดือนวันที่ 1 เวลา 04:00 (ก่อนเวลา 04:00 ยังเป็นรอบวัน/เดือนก่อน)
- เมื่อไม่มีการเคลื่อนไหว หันมุมมอง แกว่งมือ หรือใช้ไอเทมครบ `afkSeconds` จะหยุดนับเวลา นับต่อเมื่อกลับมาใช้งาน
- ใช้เวลาจริงที่เซิร์ฟเวอร์สังเกตได้ ไม่ใช่จำนวน ticks จำกัดแต่ละการสุ่มตัวอย่างไว้ที่ 5 วินาทีเพื่อไม่ชดเชยช่วงเซิร์ฟเวอร์ค้างนาน
- ไม่นับเวลา offline, spectator หรือผู้เล่นที่ตายแล้ว
- รางวัลที่ครบเงื่อนไขถูกเก็บเป็นรายการค้างรับ พร้อมสำเนาค่ารางวัล ณ เวลาที่ได้รับสิทธิ์ การแก้ config ไม่เปลี่ยนรางวัลที่ค้างอยู่
- กระเป๋าเต็ม/ยอดเงินล้นจะไม่ให้รางวัลบางส่วน ไม่โยนของลงพื้น รายการยังอยู่ในแท็บ “ค้างรับ” แม้ข้ามวันหรือเดือน
- เช็กอินสำเร็จได้แม้กระเป๋าเต็ม: สิทธิ์รายวันและรายเดือนถูกเก็บไว้ให้รับภายหลัง
- “รับทั้งหมด” เช็กอินวันนี้ด้วย แล้วรับรายการค้างรับทั้งหมดที่พื้นที่และยอดเงินรองรับได้ ที่เหลือยังค้างอยู่
- ไม่สร้างสิทธิ์เช็กอินย้อนหลังให้วันที่ไม่ได้เช็กอิน การรับรางวัลค้างจากวันเก่าไม่เพิ่มวันเช็กอินวันนี้
- ภารกิจรายวัน/รายสัปดาห์เป็นส่วนแยกสำหรับ Custom NPCs ไม่รวมในระบบนี้

## ตั้งค่ารางวัล

เซิร์ฟเวอร์สร้าง `config/neoworld/activity-rewards.json` เมื่อเริ่มครั้งแรก แก้ไฟล์และ restart เซิร์ฟเวอร์เพื่อใช้ค่าใหม่

- `daily`: รางวัลเช็กอินรายวัน
- `monthly`: รางวัลเรียงวันที่ 1–28 ต้องมี 28 รายการ
- `online`: รางวัลเรียง 15, 30, 60, 120 นาที ต้องมี 4 รายการ
- `afkSeconds`: วินาทีที่ไม่มีการใช้งานก่อนหยุดนับเวลา ค่าเริ่มต้น 300 ช่วง 1–3600
- แต่ละรางวัลมี `silver` (0–1,000,000,000) และ `items` (สูงสุด 16 รายการ ต้องมีเงินหรือไอเทมอย่างน้อยหนึ่งอย่าง)
- ไอเทมแต่ละรายการมี `item` เป็น registry ID, `count` ช่วง 1–256 และ `potion` ที่เลือกใส่ได้สำหรับ potion/splash/lingering potion

ตัวอย่างรางวัล:

```json
{
  "silver": 100,
  "items": [
    {"item": "minecraft:potion", "count": 1, "potion": "minecraft:healing"},
    {"item": "neoworld:upgrade_stone", "count": 2}
  ]
}
```

ค่าเริ่มต้นเป็นรางวัลตัวอย่างเพื่อให้ปรับสมดุลได้: รายวัน 100 Silver + ยาฟื้นฟู 1 ขวด; รายเดือนปกติ 50 Silver,
วันที่โบนัสได้ Silver เท่ากับเลขวัน ×100 พร้อม upgrade stone จำนวน 1/2/3/4; ออนไลน์ 15 นาทีได้ยา,
30 นาทีได้ 100 Silver, 60 นาทีได้ upgrade stone, 120 นาทีได้ชุดรางวัล 300 Silver + stone + ยา
ชุด 120 นาทีให้ของเข้ากระเป๋าโดยตรง ไม่มีไอเทมกล่องสุ่มใหม่

ตรวจความถูกต้องของ config เมื่อเริ่มเซิร์ฟเวอร์ หากผิดจะหยุดเริ่มระบบพร้อมแจ้งชื่อไฟล์แทนการแจกค่าผิด
ไอเทมจากมอดที่ถูกถอดออกจะยังค้างรับ โดยต้องแก้สาเหตุให้ไอเทมกลับมาพร้อมใช้งาน

## การเก็บข้อมูลและข้อจำกัด

ใช้ `neoworld:activity_data` Attachment บันทึกในข้อมูลผู้เล่นพร้อม inventory และยอดเงิน ผ่านการ save/autosave/logout ปกติ
และ copy on death ข้อมูลนี้ผูกกับ player save ของโลก ไม่ใช้ฐานข้อมูลกลาง และไม่แชร์สิทธิ์ระหว่างหลายเซิร์ฟเวอร์
ไม่ได้รับประกันการเก็บความคืบหน้าที่เปลี่ยนหลัง autosave ล่าสุดหาก process ถูก kill เช่นเดียวกับข้อมูล inventory ปกติ

AFK เป็นการตรวจการใช้งานเบื้องต้น ไม่ใช่ระบบป้องกัน macro/การเคลื่อนไหวอัตโนมัติ
ตรวจสถานะออนไลน์ทุกประมาณ 1 วินาทีและรีเฟรชหน้ากิจกรรมทุก 5 วินาที
payload ใหม่ใช้ protocol 13 ต้องอัปเดตมอดทั้ง client/server ให้ตรงกัน

ทดสอบด้วย `gradlew.bat compileJava`, `gradlew.bat activityRegressionTest` และ `gradlew.bat regressionTest`
ต้องตรวจในเกมเพิ่มเติม: layout ทุก GUI scale, รับของจริง/กระเป๋าเต็ม, AFK, logout/login, ตาย/เกิดใหม่ และ dedicated server
