# ระบบกิจกรรม NeoWorld

เปิดจาก ฮับ หรือ `/neoworld activity` (ใช้ `/neow activity` ได้ด้วย)

## โครงสร้าง GUI

- ด้านซ้ายเป็นรายการปุ่มกิจกรรม ใช้พื้นที่ลงถึงด้านล่าง แสดงได้ 9 ปุ่มต่อช่วง เลื่อนด้วยล้อเมาส์หรือปุ่มขึ้น/ลงด้านล่างเมื่อมีรายการเพิ่ม
- ด้านขวาแสดง UI ของกิจกรรมที่เลือก: รายวันเป็นการ์ด, รายเดือนเป็น 30 ช่องไอเทมพร้อมปุ่มรับใต้ช่อง, ออนไลน์มีความคืบหน้า และค้างรับเป็นรายการ
- รายเดือนเรียง 6 คอลัมน์ × 5 แถว แสดง 3 แถว (18 ช่อง) ต่อช่วง เลื่อนได้ด้วยล้อเมาส์ ปุ่มขึ้น/ลง หรือคลิก/ลาก สกรอลล์บาร์ ไม่แบ่งหน้า
- กรอบทองระบุเลขวันที่ปัจจุบันของเซิร์ฟเวอร์ ปุ่มของวันที่รับแล้ว วันอนาคต และวันที่หมดสิทธิ์จะกดไม่ได้
- ไม่มีปุ่ม “โหลดใหม่” และ “รับทั้งหมด” โหลดข้อมูลทุกกิจกรรมครั้งเดียวเมื่อเปิด UI และอัปเดตอีกครั้งเมื่อกดรับ
- สลับกิจกรรม เลื่อนปฏิทิน และเปลี่ยนหน้าของค้างรับใช้ สแนปช็อต ในหน่วยความจำ ไม่มี การโพล หรือ ลองใหม่ อัตโนมัติ
- ข้อมูลทุกหน้าถูกส่งเป็นแพ็กเก็ตที่จำกัดจำนวนรายการต่อแพ็กเก็ต และใช้เมื่อรับ สแนปช็อต ครบแล้วเท่านั้น
- `client/gui/activity/ActivityScreen.java` ดูแลกรอบ เมนู การย่อ/ขยาย และคำขอไปเซิร์ฟเวอร์
- `DailyActivityPanel`, `MonthlyActivityPanel`, `OnlineActivityPanel`, `PendingActivityPanel` แยก เลย์เอาต์, วิดเจ็ต และ เรนเดอร์ ของตัวเอง
- พัฒนา UI ใหม่โดย อิมพลีเมนต์ `ActivityPanel` และเพิ่มใน `ActivityPanelRegistry` โดยไม่ต้องแก้ เลย์เอาต์ หน้าหลัก
- `ActivityPanelContext` ให้บริการข้อมูล ปุ่ม คำขอ และ ทูลทิป พิกัดของแต่ละ แผง เริ่ม `(0,0)` ในพื้นที่ด้านขวา
- กิจกรรมใหม่ที่มีข้อมูลหรือเงื่อนไขใหม่ยังต้องเพิ่มการรองรับฝั่งเซิร์ฟเวอร์และ เพย์โหลด ตามปกติ รีจิสทรี นี้ลงทะเบียนเฉพาะ UI
- จำหน้าแยกสำหรับแต่ละกิจกรรมระหว่างสลับเมนู โดยคงการตรวจสิทธิ์รับรางวัลฝั่งเซิร์ฟเวอร์เดิม

## กติกา

- เช็กอินรายวันรับผ่านปุ่มของกิจกรรมรายวัน แยกจากรางวัลรายเดือน
- รายเดือนตรงกับเลขวันที่ของเดือน รับได้เฉพาะวันปัจจุบันและเพียงครั้งเดียว เซิร์ฟเวอร์ตรวจซ้ำทุกคำขอ
- วันที่ผ่านมาแล้วหมดสิทธิ์ ไม่รับย้อนหลังและไม่ย้ายไปกล่องค้างรับ แม้เคยลองรับตอนกระเป๋าเต็ม
- กระเป๋าหรือยอดเงินเต็มจะยังไม่บันทึกว่ารับสำเร็จ ลองรับได้อีกภายในวันเดียวกันก่อน 04:00
- มี 30 ช่อง วันที่ 31 ไม่มีรางวัลรายเดือน เดือนกุมภาพันธ์ช่องวันที่ไม่มีอยู่จะรับไม่ได้
- รายเดือนมีโบนัสเริ่มต้นวันที่ 7, 14, 21 และ 28
- ออนไลน์สะสม 15 / 30 / 60 / 120 นาทีต่อวัน ออกจากเกมแล้วกลับมาเล่นต่อได้
- รีเซ็ตเวลา 04:00 Asia/Bangkok รายเดือนวันที่ 1 เวลา 04:00 (ก่อนเวลา 04:00 ยังเป็นรอบวัน/เดือนก่อน)
- เมื่อไม่มีการเคลื่อนไหว หันมุมมอง แกว่งมือ หรือใช้ไอเทมครบ `afkSeconds` จะหยุดนับเวลา นับต่อเมื่อกลับมาใช้งาน
- ใช้เวลาจริงที่เซิร์ฟเวอร์สังเกตได้ ไม่ใช่จำนวน ทิก จำกัดแต่ละการสุ่มตัวอย่างไว้ที่ 5 วินาทีเพื่อไม่ชดเชยช่วงเซิร์ฟเวอร์ค้างนาน
- ไม่นับเวลา ออฟไลน์, ผู้ชม หรือผู้เล่นที่ตายแล้ว
- รางวัลรายวัน/ออนไลน์ที่ครบเงื่อนไขถูกเก็บเป็นรายการค้างรับ พร้อมสำเนาค่ารางวัล ณ เวลาที่ได้รับสิทธิ์ การแก้ คอนฟิก ไม่เปลี่ยนรางวัลที่ค้างอยู่
- กระเป๋าเต็ม/ยอดเงินล้นจะไม่ให้รางวัลบางส่วน ไม่โยนของลงพื้น รายวัน/ออนไลน์ยังอยู่ในแท็บ “ค้างรับ” แม้ข้ามวันหรือเดือน
- เช็กอินรายวันสำเร็จได้แม้กระเป๋าเต็ม และรับของรายวันภายหลังได้ กติกานี้ไม่ใช้กับรายเดือน
- ไม่สร้างสิทธิ์เช็กอินย้อนหลังให้วันที่ไม่ได้เช็กอิน การรับรางวัลค้างจากวันเก่าไม่เพิ่มวันเช็กอินวันนี้
- ภารกิจรายวัน/รายสัปดาห์เป็นส่วนแยกสำหรับ Custom NPCs ไม่รวมในระบบนี้

## ตั้งค่ารางวัล

เซิร์ฟเวอร์สร้าง `config/neoworld/activity-rewards.json` เมื่อเริ่มครั้งแรก แก้ไฟล์และ รีสตาร์ต เซิร์ฟเวอร์เพื่อใช้ค่าใหม่

- `daily`: รางวัลเช็กอินรายวัน
- `monthly`: รางวัลเรียงวันที่ 1–30 ต้องมี 30 รายการ ไฟล์เดิม 28 รายการรองรับโดยเติมค่าเริ่มต้นวันที่ 29–30 ในหน่วยความจำ ไม่เขียนทับไฟล์เดิม
- `online`: รางวัลเรียง 15, 30, 60, 120 นาที ต้องมี 4 รายการ
- `afkSeconds`: วินาทีที่ไม่มีการใช้งานก่อนหยุดนับเวลา ค่าเริ่มต้น 300 ช่วง 1–3600
- แต่ละรางวัลกำหนดผ่าน `items` (สูงสุด 16 รายการ ต้องมีไอเทมอย่างน้อยหนึ่งอย่าง) เงินใช้ไอเทมเหรียญและระบบแปลงเหรียญเดิม ไม่เพิ่มยอดเงินโดยตรง
- `silver` เป็นค่าเก่าสำหรับความเข้ากันได้ ถ้ายังมีค่าจะถูกแปลงเป็น silver_coin ในหน่วยความจำ แนะนำให้ลบหรือใส่ 0 เมื่อกำหนดเหรียญใน items แล้ว
- ไอเทมแต่ละรายการมี `item` เป็น รีจิสทรี ID, `count` ช่วง 1–256 และ `potion` ที่เลือกใส่ได้สำหรับ potion/splash/lingering potion
- เหรียญใช้ `neoworld:silver_coin`, `neoworld:diamond_coin` พร้อม `coinValue` มูลค่าต่อชิ้น (1–1,000,000,000 ค่าเริ่มต้น 1) มูลค่ารวม = count × coinValue

ตัวอย่างรางวัล:

```json
{
  "items": [
    {"item": "neoworld:silver_coin", "count": 1, "coinValue": 100},
    {"item": "minecraft:potion", "count": 1, "potion": "minecraft:healing"},
    {"item": "neoworld:upgrade_stone", "count": 2}
  ]
}
```

ค่าเริ่มต้นเป็นรางวัลตัวอย่างเพื่อให้ปรับสมดุลได้ โดยเงินทั้งหมดแจกเป็นเหรียญมูลค่าตามกำหนด: รายวัน 100 Silver + ยาฟื้นฟู 1 ขวด; รายเดือนปกติ 50 Silver,
วันที่โบนัสได้ Silver เท่ากับเลขวัน ×100 พร้อม หินอัปเกรด จำนวน 1/2/3/4; ออนไลน์ 15 นาทีได้ยา,
30 นาทีได้ 100 Silver, 60 นาทีได้ หินอัปเกรด, 120 นาทีได้ชุดรางวัล 300 Silver + หิน + ยา
ชุด 120 นาทีให้ของเข้ากระเป๋าโดยตรง ไม่มีไอเทมกล่องสุ่มใหม่

ตรวจความถูกต้องของ คอนฟิก เมื่อเริ่มเซิร์ฟเวอร์ หากผิดจะหยุดเริ่มระบบพร้อมแจ้งชื่อไฟล์แทนการแจกค่าผิด
ไอเทมรายวัน/ออนไลน์จากมอดที่ถูกถอดออกจะยังค้างรับ โดยต้องแก้สาเหตุให้ไอเทมกลับมาพร้อมใช้งาน
สำหรับรายเดือนต้องแก้ก่อนสิ้นสุดวัน มิฉะนั้นหมดสิทธิ์ตามกติกา

## การเก็บข้อมูลและข้อจำกัด

ใช้ `neoworld:activity_data` แอตแทชเมนต์ บันทึกในข้อมูลผู้เล่นพร้อม คลัง และยอดเงิน ผ่านการ บันทึก/บันทึกอัตโนมัติ/ออกจากเกม ปกติ
และ คัดลอกเมื่อตาย ข้อมูลนี้ผูกกับ เซฟผู้เล่น ของโลก ไม่ใช้ฐานข้อมูลกลาง และไม่แชร์สิทธิ์ระหว่างหลายเซิร์ฟเวอร์
ไม่ได้รับประกันการเก็บความคืบหน้าที่เปลี่ยนหลัง เซฟอัตโนมัติ ล่าสุดหาก โปรเซสถูกบังคับหยุด เช่นเดียวกับข้อมูล คลัง ปกติ

AFK เป็นการตรวจการใช้งานเบื้องต้น ไม่ใช่ระบบป้องกัน macro/การเคลื่อนไหวอัตโนมัติ
เซิร์ฟเวอร์นับเวลาออนไลน์ตามปกติ แต่ไม่ส่งข้อมูล GUI ตามเวลา ข้อมูลหน้าจอคงตาม สแนปช็อต จนกดรับหรือปิดแล้วเปิดใหม่
เมื่อคำขอหมดเวลาจะแจ้งให้ปิดและเปิดใหม่ ไม่ส่งคำขอซ้ำเอง
สแนปช็อต กิจกรรมใช้ โปรโตคอล 17 ต้องอัปเดตมอดทั้ง ไคลเอนต์/เซิร์ฟเวอร์ ให้ตรงกัน
ข้อมูลผู้เล่นเดิมที่ยังไม่มี มาสก์ ปฏิทินจะคงดัชนี หมุดหมาย เดิมที่เคยได้รับสิทธิ์เป็นรับแล้วเพื่อกันแจกซ้ำ
รายการรายเดือนค้างรับจากกติกาสะสมเดิมถูกตัดออกเมื่อเปิดรอบกิจกรรม และไม่สามารถรับผ่านแท็บค้างรับได้

ทดสอบด้วย `gradlew.bat compileJava`, `gradlew.bat activityRegressionTest` และ `gradlew.bat regressionTest`
ต้องตรวจในเกมเพิ่มเติม: เลย์เอาต์ ทุก สเกล GUI, รับของจริง/กระเป๋าเต็ม, AFK, logout/login, ตาย/เกิดใหม่ และ เซิร์ฟเวอร์แยก
