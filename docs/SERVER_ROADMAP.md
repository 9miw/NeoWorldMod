# NeoWorld Server Roadmap
เอกสารนี้สรุปสถานะระบบเซิร์ฟเวอร์จากโค้ดปัจจุบัน และจัดลำดับงานที่ควรทำต่อเพื่อไปสู่เซิร์ฟเวอร์ MMORPG x Survival ที่เปิดทดสอบได้จริง

## สถานะระบบตอนนี้

### พร้อมใช้งานในม็อด

- ระบบเลเวลผู้เล่น 1-100 พร้อม EXP, การเลเวลอัป, เอฟเฟกต์เสียง/อนุภาค และการซิงค์ HUD
- ระบบบันทึกข้อมูลผู้เล่นด้วย NeoForge Data Attachments เช่น เลเวล, EXP และยอดเงิน
- ระบบเงิน 3 สกุล: Silver, Gold และ Diamond
- ฝากเหรียญอัตโนมัติเมื่อเก็บจากพื้นหรือมีเหรียญในกระเป๋า Survival
- ป้องกันยอดเงินล้นเพดาน `long` และปฏิเสธธุรกรรมผิดปกติ
- HUD แสดงเลเวล, EXP และยอดเงินฝั่ง Client
- คำสั่ง `/neoworld`, `/neow`, `/level`, `/eco` และ `/economy`
- Permission ผ่าน NeoForge Permission API รองรับ permission handler เช่น LuckPerms และ fallback เป็น OP level
- เชื่อม Custom NPCs Availability ให้ใช้เลเวล NeoWorld แทน vanilla EXP level
- เชื่อมร้านค้า Custom NPCs ให้จ่ายด้วยยอดเงินในระบบ Economy แทนการใช้ไอเทมเหรียญในกระเป๋า
- มี regression test ครอบคลุมกรณีเงินล้น, การคิดราคาร้านค้า 2 ช่อง และการบันทึกข้อมูลหลัก

### พร้อมเป็นฐาน แต่ยังต้องทดสอบในเกมจริง

- GUI/HUD ฝั่ง Client บนหน้าจอหลายขนาด
- Mixin กับ Custom NPCs รุ่นจริงทั้ง Client และ Server
- Permission deny/allow ผ่าน LuckPerms
- การซิงค์ข้อมูลหลังออกเกม เข้าใหม่ ตาย และเปลี่ยนมิติ
- การวางร้านค้าราคาหลายช่องและหลายสกุลใน Custom NPCs

### ยังไม่เปิดใช้งาน

- EXP จากการฆ่ามอนสเตอร์ เควสต์ ดันเจี้ยน และบอส
- เงินดรอปจากมอนสเตอร์หรือกิจกรรม
- Epic Fight attribute scaling ตามเลเวล
- การจำกัดอาวุธ ชุดเกราะ และสกิลตามเลเวล
- ระบบโซน, safe zone, wild zone, dungeon และ raid
- ระบบ claim / protection / PvP territory
- ตลาดผู้เล่น, ภาษี, money sink และ death penalty
- เควสต์หลัก, daily quest, NPC progression และ reward table
- การตั้งค่า balance ผ่าน config ภายนอกสำหรับทีมดูแลเซิร์ฟเวอร์

## Roadmap ต่อไป

### Phase 0: Stabilize Core ก่อนเปิดให้ทีมลอง

เป้าหมาย: ทำให้ระบบที่มีแล้วไม่พังเมื่อใช้จริงบนเซิร์ฟเวอร์

- ทดสอบ build ด้วย JDK 21 และ NeoForge 1.21.1
- ทดสอบ Client + Dedicated Server พร้อม Custom NPCs รุ่นที่กำหนด
- ตรวจ auto deposit เมื่อยอดเงินเต็ม ต้องไม่ทำให้เหรียญหาย
- ตรวจร้านค้า NPC กรณีราคาปกติ, ราคาติดลบ, ราคาล้น และสองช่องสกุลเดียวกัน
- ตรวจ LuckPerms สำหรับคำสั่งผู้เล่นและคำสั่งผู้ดูแล
- เขียน checklist สำหรับทีมทดสอบในเกมจริง

ผลลัพธ์ที่ต้องได้: ไฟล์ JAR ใช้บนเซิร์ฟเวอร์ทดสอบได้ และระบบเลเวล/เงิน/ร้านค้าพื้นฐานเชื่อถือได้

### Phase 1: Player Progression Loop

เป้าหมาย: ให้ผู้เล่นมีเหตุผลในการเก็บเลเวล

- เพิ่ม EXP reward จากมอนสเตอร์
- เพิ่ม EXP reward จากคำสั่ง/ระบบเควสต์ของ Custom NPCs
- เพิ่มตาราง EXP ตามชนิดมอนสเตอร์และระดับพื้นที่
- เพิ่มข้อความ/Actionbar เมื่อได้รับ EXP
- เพิ่ม config สำหรับปรับสูตร EXP และ max level โดยไม่ต้องแก้โค้ด
- เพิ่ม command สำหรับตรวจ/รีเซ็ต progression ในช่วงทดสอบ

ผลลัพธ์ที่ต้องได้: ผู้เล่นเล่น PvE หรือทำเควสต์แล้วเลเวลเพิ่มได้จริงโดยไม่ต้องให้แอดมินเพิ่ม EXP เอง

### Phase 2: Economy Gameplay Loop

เป้าหมาย: ทำให้เงินมีที่มาและที่ใช้ ไม่เฟ้อเร็วเกินไป

- เพิ่ม coin/money reward จากมอนสเตอร์, เควสต์ และดันเจี้ยน
- กำหนด rate เงินตามโซนและระดับความยาก
- เพิ่ม money sink เช่น ค่า teleport, ค่าซ่อม, ค่าธรรมเนียมตลาด, ค่าเข้า dungeon
- เพิ่ม log ธุรกรรมสำคัญสำหรับตรวจ exploit
- เพิ่ม command/admin tool สำหรับดูยอดรวมเศรษฐกิจเบื้องต้น
- ทำ balance sheet สำหรับรายรับ/รายจ่ายต่อชั่วโมงของผู้เล่น

ผลลัพธ์ที่ต้องได้: ผู้เล่นหาเงินและใช้เงินวนในระบบได้ โดยทีมแอดมินมีเครื่องมือตรวจเงินเฟ้อ

### Phase 3: Epic Fight Integration

เป้าหมาย: เชื่อมเลเวลกับพลังต่อสู้แบบ Action RPG

- เพิ่ม attribute scaling ตามเลเวล เช่น stamina, stamina regen, stun armor และ max health
- จำกัดอาวุธ/ชุดเกราะตามเลเวลขั้นต่ำ
- เพิ่ม tooltip บอกเลเวลที่ต้องการเมื่อถือหรือชี้ไอเทม
- ป้องกันการใช้อาวุธที่เลเวลไม่ถึงใน combat จริง
- วางตารางปลดล็อก skill slot หรือ skill book ตามช่วงเลเวล
- ทดสอบ balance กับ Epic Fight ใน PvE และ PvP

ผลลัพธ์ที่ต้องได้: เลเวลส่งผลต่อ combat อย่างชัดเจน แต่ไม่ทำให้ผู้เล่นใหม่สู้ไม่ได้เลย

### Phase 4: World Zones และ Survival Rules

เป้าหมาย: แยกพื้นที่ถาวรของผู้เล่นออกจากพื้นที่ฟาร์มทรัพยากรที่รีเซ็ตได้

เซิร์ฟเวอร์มี 2 โลกหลัก:

1. **โลกสร้างบ้าน (Home World)**
   - เป็นโลกถาวรสำหรับเมืองหลัก บ้านผู้เล่น ฟาร์ม ร้านค้า และโรงงาน Create
   - มี Safe Zone ที่จุดเกิด และพื้นที่ Claim สำหรับผู้เล่น
   - ปิดหรือจำกัด PvP พร้อมระบบป้องกันการขโมยและทำลายสิ่งปลูกสร้าง
   - ไม่รีเซ็ตโลก ยกเว้นมีการประกาศย้ายหรือซ่อมแผนที่เป็นกรณีพิเศษ
   - จำกัดทรัพยากรหายากและการเกิดมอนสเตอร์ที่ให้รางวัลสูง เพื่อลดการขุดทำลายภูมิประเทศ

2. **โลกหาของ (Resource World)**
   - ใช้ขุดแร่ ตัดไม้ ล่ามอนสเตอร์ หาไอเทมหายาก และวางทางเข้าดันเจี้ยน
   - แบ่งความยากเป็น Outer Frontier / Dangerous Wilds / Dungeon / Warzone
   - เพิ่ม mob scaling, spawn table และ resource tier ตามระยะหรือโซน
   - เปิด PvP เฉพาะโซนที่กำหนด และไม่อนุญาตให้ Claim ถาวร
   - รีเซ็ตตามรอบที่ประกาศล่วงหน้า โดยต้องย้ายไอเทมกลับโลกสร้างบ้านก่อนวันรีเซ็ต

- ทำ Portal หรือ Teleport Hub เชื่อมสองโลก และกำหนดจุดกลับที่ปลอดภัย
- กำหนดรายการไอเทมที่ห้ามนำข้ามโลก หากจำเป็นต่อการควบคุมเศรษฐกิจ
- ทดสอบข้อมูลผู้เล่น เงิน เลเวล และ Inventory เมื่อเดินทางข้ามโลก

ผลลัพธ์ที่ต้องได้: สิ่งปลูกสร้างของผู้เล่นปลอดภัยในโลกถาวร ขณะที่โลกหาของสามารถรีเซ็ตเพื่อเติมทรัพยากรและคอนเทนต์ได้

### Phase 5: Quests, Dungeons และ Boss Content

เป้าหมาย: สร้างคอนเทนต์หลักสำหรับเล่นเป็นปาร์ตี้

- ทำเควสต์เริ่มต้นสอนระบบเลเวล เงิน ร้านค้า และพื้นที่
- ทำ daily/weekly quest สำหรับวนเล่น
- สร้าง dungeon tier แรกสำหรับ Lv. 10-20
- เพิ่ม boss reward table แยก EXP, เงิน, วัตถุดิบ และ skill book
- เพิ่ม cooldown หรือ entry cost เพื่อคุมการฟาร์ม
- ทำรอบทดสอบ balance กับปาร์ตี้ 3-5 คน

ผลลัพธ์ที่ต้องได้: มี gameplay loop หลักครบ เล่นคนเดียวได้ และมีเหตุผลให้รวมปาร์ตี้

### Phase 6: Market, Guild และ Endgame

เป้าหมาย: รองรับสังคมผู้เล่นและเศรษฐกิจระยะยาว

- เพิ่มตลาดผู้เล่นหรือ auction house
- เพิ่มภาษีซื้อขายและราคาค่าธรรมเนียมตามมูลค่า
- วางระบบ guild/clan และสิทธิ์พื้นที่
- ทำ PvP territory หรือ warzone reward
- เพิ่ม endgame dungeon/raid และ rare material
- เพิ่ม leaderboard เศรษฐกิจ เลเวล และ dungeon clear

ผลลัพธ์ที่ต้องได้: ผู้เล่นมีเป้าหมายระยะยาวนอกเหนือจากการเก็บเลเวล

### Phase 7: Alpha, Beta และ Launch

เป้าหมาย: เปิดทดสอบเป็นรอบโดยลดความเสี่ยงก่อนเปิดจริง

- Closed Alpha: ทีมงานและผู้เล่นกลุ่มเล็ก ทดสอบระบบหลักและ bug ร้ายแรง
- Balance Alpha: ปรับ EXP, เงิน, drop rate, dungeon difficulty และ money sink
- Open Beta: เปิดผู้เล่นมากขึ้นเพื่อทดสอบ performance และ economy จริง
- Wipe/No-wipe decision: ตัดสินใจจากความเสถียรและ exploit ที่พบ
- Launch Season 1: เปิดจริงพร้อม changelog, rulebook และคู่มือเริ่มเล่น

ผลลัพธ์ที่ต้องได้: เซิร์ฟเวอร์เปิดได้แบบมีแผน rollback, backup และทีมดูแลพร้อมรับปัญหา

## ลำดับความสำคัญแนะนำ

1. ทำ Phase 0 ให้จบก่อน เพราะเป็นฐานของทุกระบบ
2. ต่อด้วย Phase 1 และ Phase 2 เพื่อให้ผู้เล่นมี loop พื้นฐาน: เล่น ได้ EXP ได้เงิน ใช้เงิน
3. ทำ Phase 3 หลัง loop พื้นฐานนิ่ง เพราะ combat balance ต้องอิงค่า EXP และเงิน
4. ทำ Phase 4-5 เพื่อสร้างโลกและคอนเทนต์จริง
5. ทำ Phase 6-7 เมื่อระบบหลักเริ่มนิ่งและมีทีมทดสอบ

## Milestone สำหรับรอบถัดไป

เป้าหมายที่ควรทำทันทีในรอบพัฒนาถัดไป:

- เพิ่ม EXP จากการฆ่ามอนสเตอร์
- เพิ่ม reward config พื้นฐาน
- เพิ่ม money drop หรือ reward จากมอนสเตอร์แบบควบคุมได้
- เพิ่ม checklist ทดสอบ dedicated server
- ทดสอบ Custom NPCs shop + LuckPerms ในเกมจริง
