# การจัดเก็บระบบฉายา

## รายการฉายา

รายการฉายาเก็บใน H2 หรือ MariaDB ตามการตั้งค่าฐานข้อมูล NeoWorld เดิม ตาราง `<prefix>title_catalogue` เป็นข้อมูลหลัก ส่วน `TitleRegistry` เป็นแคชสำหรับอ่านในเกม

Migration รุ่น 11 สร้างตารางรายการฉายา โดยการเริ่มระบบครั้งแรกจะนำเข้าจาก `config/neoworld/titles.json` ถ้ามีไฟล์อยู่ หากไม่มีจะใช้ `src/main/resources/data/neoworld/default_titles.json` ซึ่งมีฉายา 12 ชื่อ โดยไม่สร้าง JSON ใหม่ การนำเข้ารายการและตัวบันทึก `title_catalogue_imported_v1` ใน `<prefix>metadata` อยู่ในธุรกรรมเดียวกัน เก็บไฟล์ JSON เดิมไว้โดยไม่แก้ไข

หลังนำเข้าสำเร็จจะโหลดจากฐานข้อมูลเท่านั้น การแก้ JSON เดิมจะไม่มีผล แม้ล้างรายการฉายาในฐานข้อมูลจนว่างก็จะไม่เติมฉายาเริ่มต้นกลับมา หากนำเข้าล้มเหลวจะ rollback และหยุดเริ่มระบบเพื่อให้แก้สาเหตุแล้วเริ่มใหม่ โดยไม่ทิ้งสถานะว่านำเข้าสำเร็จ หากพบตารางมีรายการแต่ไม่มีตัวบันทึกการนำเข้า ระบบจะหยุดเพื่อหลีกเลี่ยงการเขียนทับข้อมูลที่ไม่ทราบที่มา ไม่ควรลบตัวบันทึกนี้เพื่อบังคับนำเข้าใหม่

แต่ละรายการมี `id`, `name`, `display`, `description`, `category` (`GENERAL` / `HUMOROUS`), `rarity` (`COMMON` / `RARE`), `requirement`, `color` (`#RRGGBB`), `effect` และ `condition` (`metric`, `target`)

`name` คือชื่อฉายาในรายการ GUI และคำสั่ง ส่วน `display` คือข้อความเหนือหัวและในตัวอย่างผู้เล่น เช่น `name: "ผู้พิชิตไร้บาดแผล"`, `display: "✦ ผู้ไร้บาดแผล ✦"` ทั้งคู่ยาวไม่เกิน 64 ตัวอักษร ไม่รองรับ อักขระควบคุม หรือรหัสสี `§` ให้ใช้ `color` แยกต่างหาก JSON เก่าที่ไม่มี `display` หรือมีค่า `null` จะใช้ `name` แทน ไม่ต้องย้ายข้อมูลผู้เล่นเพราะฐานข้อมูลอ้างอิง `id` เดิม

แก้ชื่อ คำอธิบาย สี หรือเงื่อนไขในฐานข้อมูลได้ แต่ควรคง `title_id` เดิมเพื่อรักษาการปลดล็อกของผู้เล่น คอลัมน์ `title_name` คือ `name`, `display_text` คือ `display`, `requirement_text` คือ `requirement`, `metric` และ `target` คือเงื่อนไข และ `sort_order` คือลำดับแสดง เก็บหมวดและความหายากเป็นชื่อ enum เดิม ไม่ได้เพิ่มหน้าแก้ไขแอดมินในงานย้ายข้อมูลนี้

ใช้ `/neow title admin reload` หรือ `/neoworld title admin reload` ด้วยสิทธิ์ OP ระดับ 2 เพื่ออ่านรายการล่าสุดจากฐานข้อมูลแบบแยกเธรด ไม่อ่าน JSON และไม่เปลี่ยนแคชก่อนอ่านสำเร็จ หากข้อมูลในฐานข้อมูลผิดรูปแบบจะคงรายการเดิมไว้ หากผิดตอนเริ่มเซิร์ฟเวอร์จะหยุดเริ่มระบบพร้อมรายงานข้อผิดพลาด

`condition.metric = manual` ใช้กับเงื่อนไขที่ยังไม่กำหนดรายละเอียด ค่าเงื่อนไขเป็นข้อมูลเตรียมไว้ ยังไม่ได้เชื่อม อีเวนต์ ปลดล็อกอัตโนมัติ `effect` ปัจจุบันเป็น `none` และยังไม่มีตัวเรนเดอร์ อนุภาค

## ข้อมูลผู้เล่น

คำสั่งผู้เล่นทั่วไป (ใช้ `/neoworld` แทน `/neow` ได้):

- `/neow title list`: ดูฉายาที่ปลดล็อกพร้อมชื่อ ID และสถานะกำลังใส่
- `/neow title equip <ID>`: ใส่หรือเปลี่ยนฉายาที่ปลดล็อกแล้ว เช่น `/neow title equip traveler` มี การเติมคำด้วย Tab เฉพาะฉายาที่ปลดล็อกและยังอยู่ในรายการ
- `/neow title clear`: ถอดฉายา โดยยังเก็บรายการที่ปลดล็อกไว้
- `/neow title gui`: เปิดหน้าจัดการฉายา พร้อมรายการแบ่งหน้า ค้นหาชื่อ/ID ตัวกรองทั่วไป/หายาก/เชิงขำ ตัวอย่างผู้เล่น รายละเอียดฉายา ปุ่มใส่/ถอด และเปิด–ปิดการแสดงฉายาเหนือหัว

คำสั่งผู้เล่นใช้ได้เฉพาะผู้เล่นและจัดการข้อมูลของตัวเอง ไม่ต้องมี OP เซิร์ฟเวอร์ ตรวจสิทธิ์การใส่จากฐานข้อมูล และแจ้งสำเร็จหลัง คอมมิต เท่านั้น

GUI ใช้กรอบ PNG Market และ `NeoButton` กลาง ข้อความทั้งหมดเรนเดอร์ขณะเล่น ไคลเอนต์ ส่ง แอ็กชัน โดยไม่มี UUID เป้าหมาย เซิร์ฟเวอร์ ใช้ผู้ส่งแพ็กเก็ตเป็นเจ้าของข้อมูลและกรอง/แบ่งหน้าให้ครั้งละ 5 รายการ คำตอบมี ID คำขอ เพื่อทิ้งผลเก่าหลังปิดหรือเปลี่ยนหน้าจอ ระหว่างบันทึกจะปิดปุ่มทำรายการ หากรอเกิน 10 วินาทีให้โหลดข้อมูลใหม่ก่อนทำรายการต่อ การค้นหาหน่วง 8 ทิก การตั้งค่าเอฟเฟกต์ยังไม่เปิดให้ใช้งานเพราะยังไม่มีตัวเรนเดอร์ อนุภาค

สถานะการตรวจสอบ GUI: คอมไพล์และทดสอบข้อมูล/เพย์โหลด ได้ แต่ยังต้องตรวจภาพจริงในเกมเทียบมอคอัพ โดยเฉพาะตำแหน่งตัวอย่างผู้เล่น ขนาดฟอนต์ และ สเกล GUI

ใช้ฐานข้อมูล H2 หรือ MariaDB ที่ตั้งค่าไว้ใน NeoWorld และ พรีฟิกซ์ตาราง เดิม การย้ายสคีมา รุ่น 4 เพิ่ม:

- `title_players`: UUID, ฉายาที่ใส่, การแสดงเหนือหัว, การแสดงเอฟเฟกต์
- `title_unlocks`: UUID, ID ฉายา, วันที่ได้รับเป็น มิลลิวินาทีแบบ Unix
- `title_progress`: UUID, ชื่อ metric, ค่าความคืบหน้า
- `title_discoveries`: UUID, metric, ID สิ่งที่ค้นพบ เพื่อไม่นับพื้นที่ซ้ำ

นำเข้า แอตแทชเมนต์ เซฟเดิมในครั้งแรกที่ผู้เล่นเข้าเกม โดยใช้วันที่นำเข้าแทนวันที่ได้รับเดิมซึ่งไม่เคยบันทึก การมีแถวใน `title_players` หมายถึงนำเข้าเสร็จแล้ว จึงไม่ดึงฉายาที่ถูกถอนกลับมาจากเซฟเก่า การนำเข้าทั้งหมดอยู่ใน ธุรกรรม เดียว

ฐานข้อมูลเป็นข้อมูลหลัก การเปลี่ยนแปลงต้องผ่าน `TitleService` ซึ่งมี API รับ UUID สำหรับอ่าน ปลดล็อก ถอน ใส่ ถอด ตั้งค่าการแสดงผล ความคืบหน้า และพื้นที่ค้นพบ รองรับผู้เล่นออฟไลน์ที่เคยเข้าเกมและนำเข้าเสร็จแล้ว

คำสั่ง `/neow title admin unlockall <ผู้เล่น>` หรือ `/neoworld title admin unlockall <ผู้เล่น>` ใช้สิทธิ์ OP ระดับ 2 ปลดล็อกฉายาทั้งหมดในรายการปัจจุบันให้ผู้เล่นออนไลน์ที่ระบุ โดยบันทึกใน ธุรกรรม เดียว คงวันที่ได้รับของฉายาที่มีอยู่แล้ว และไม่เปลี่ยนฉายาที่ใส่ ความคืบหน้า หรือตั้งค่าการแสดงผล ตัวอย่าง `/neow title admin unlockall Miw` หรือ `/neow title admin unlockall @s` คำสั่งแจ้งสำเร็จหลัง คอมมิต และบันทึกผู้สั่ง/ผู้รับใน ล็อก

เรียก API บน เธรดเซิร์ฟเวอร์ งาน SQL ทำใน เวิร์กเกอร์ แยก จากนั้นอัปเดต แคช และส่งข้อมูลไป ไคลเอนต์ เฉพาะเมื่อ คอมมิต สำเร็จ ถ้าโหลดล้มเหลวจะซ่อนฉายาชั่วคราวและลองใหม่ทุก 5 วินาที ไม่มีการนำ แคช หรือ แอตแทชเมนต์ กลับมาเขียนทับฐานข้อมูลตอนออกเกม การใช้ฐานข้อมูลเดียวกันกับหลาย เซิร์ฟเวอร์ พร้อมกันยังไม่มีระบบกระจายการเปลี่ยนแปลง แคช ระหว่าง เซิร์ฟเวอร์

ไคลเอนต์ รับข้อความ `display` และสีจาก เซิร์ฟเวอร์ โดยตรง จึงไม่ต้องมี JSON ตรงกัน GUI รับ `name` และ `display` แยกกัน โปรโตคอล ปัจจุบันเป็นรุ่น 5 ทั้ง ไคลเอนต์ และ เซิร์ฟเวอร์ ต้องอัปเดตมอดพร้อมกัน
