# ระบบจัดการโลก

ระบบฝั่งเซิร์ฟเวอร์สำหรับย้ายผู้เล่นและรีมิติที่โหลดอยู่ โดยไม่ต้องปิดเซิร์ฟเวอร์ คำสั่งทั้งหมดใช้สิทธิ์แอดมินระดับ 2 หรือ console และใช้ `/neow` แทน `/neoworld` ได้

## คำสั่ง

| คำสั่ง | การทำงาน |
| --- | --- |
| `/neoworld world` | แสดงวิธีใช้ |
| `/neoworld world list` | แสดงโลกที่โหลดอยู่ โลกที่เคยตั้งรี รอบเวลา และสถานะรี |
| `/neoworld world tp <ผู้เล่น> <โลก> <x> <y> <z>` | ย้ายผู้เล่นไปโลกและพิกัดที่กำหนด รองรับพิกัด `~` และ `^` ตามตำแหน่งผู้สั่ง |
| `/neoworld world random <ผู้เล่น> <โลก> [รัศมี]` | ค้นหาจุดสุ่มที่มีพื้นยืนและพื้นที่ว่างก่อนย้ายผู้เล่น |
| `/neoworld world reset add <โลก> <วัน>` | เพิ่มหรือเปลี่ยนรอบรีอัตโนมัติ เริ่มนับรอบใหม่ทันที |
| `/neoworld world reset remove <โลก>` | ยกเลิกรีอัตโนมัติ โดยไม่ลบโลกหรือประวัติรี |
| `/neoworld world reset now <โลก> confirm` | เข้าคิวรีทันที แม้โลกนั้นไม่ได้ตั้งรีอัตโนมัติ |

`<ผู้เล่น>` ใช้ชื่อผู้เล่นหรือ selector เช่น `@a` และ `@s` ได้ `<โลก>` ใช้ชื่อมิติเต็ม เช่น `neoworld:resource_world`, `neoworld:build_world`, `minecraft:the_nether`, `minecraft:the_end` มีคำแนะนำชื่อโลกขณะพิมพ์

ตัวอย่าง:

```text
/neoworld world tp Miw neoworld:build_world 100 80 200
/neoworld world random Miw neoworld:resource_world
/neoworld world random @a minecraft:the_nether 500
/neoworld world reset add neoworld:resource_world 7
/neoworld world reset add minecraft:the_nether 14
/neoworld world reset now neoworld:resource_world confirm
/neoworld world reset remove minecraft:the_nether
```

รอบรีตั้งได้ 1–3650 วันตามเวลาจริง ระบบจำเวลาหลังรีสตาร์ต หากปิดเซิร์ฟเวอร์เลยกำหนดจะเข้าคิวรีหลังเปิดอีกครั้ง หากสั่งรีด้วยมือในโลกที่ตั้งรีอัตโนมัติ รอบถัดไปจะเริ่มนับจากการรีสำเร็จ คำสั่ง remove ไม่ยกเลิกงานที่เข้าคิวหรือกำลังรีอยู่

## การย้ายผู้เล่น

คำสั่ง tp ตรวจขอบเขตและความสูงของโลก แต่ใช้พิกัดที่แอดมินระบุโดยตรง แอดมินต้องเลือกพื้นที่ยืนที่เหมาะสม

คำสั่ง random สุ่มในกรอบสี่เหลี่ยม ±รัศมีรอบศูนย์กลาง world border และจำกัดให้อยู่ภายใน border ค่าเริ่มต้น 1000 บล็อก ตั้งได้ 1–10000 บล็อก ทำทีละงานทั้งเซิร์ฟเวอร์ โดยสุ่มตรวจ chunk ที่โหลดอยู่ก่อน 16 ตำแหน่ง หากไม่พบจึงขอโหลดได้ไม่เกิน 16 ตำแหน่ง เว้นการขอโหลดอย่างน้อย 20 tick และรอคำขอเดิมเสร็จก่อนขอครั้งต่อไป แต่ละงานมีเวลา 2 นาทีเริ่มเมื่อถึงหัวคิว โดยไม่รอบน server thread รองรับคิวผู้เล่นสูงสุด 32 คน มีคำสั่งสุ่มค้างได้หนึ่งคำสั่งต่อผู้เล่น การสร้าง chunk ใหม่และการโหลดพื้นที่รอบผู้เล่นหลังย้ายยังใช้ทรัพยากรเซิร์ฟเวอร์

จุดสุ่มต้องมีพื้นแข็งและช่องอากาศสองบล็อก หลีกเลี่ยงพื้นลาวา น้ำ magma campfire cactus และ powder snow สำหรับโลกที่มีเพดาน เช่น Nether จะค้นหาพื้นที่ด้านล่างเพดาน หากไม่พบจุดที่ปลอดภัยจะรายงานความล้มเหลวแทนการย้ายผู้เล่น

## การรีโลก

ข้อความเตือนก่อนรีและเริ่มรีส่งเฉพาะผู้เล่นที่อยู่ในมิตินั้น โดยใช้คำนำหน้า `[จัดการโลก]` และไม่แสดงชื่อโลก เช่น `[จัดการโลก] โลกนี้จะรีเซ็ตในอีก 5 นาที กรุณาเก็บของและออกจากโลก` ช่วง 10 → 1 วินาทีใช้ข้อความสั้นโดยไม่มีคำเตือนเก็บของซ้ำ เมื่อรีสำเร็จจะแจ้งเฉพาะผู้เล่นที่ระบบย้ายออกและยังออนไลน์อยู่ หากรีล้มเหลวจะแจ้งผู้เล่นที่ยังอยู่ในโลกนั้นและผู้เล่นที่ถูกย้ายออก ไม่ประกาศไปยังผู้เล่นอื่น ชื่อโลกยังแสดงในคำสั่งแอดมินและ log เพื่อระบุโลกที่จัดการ

รองรับมิติที่โหลดด้วย `ServerLevel` ปกติ รวมถึงมิติ NeoWorld, Nether และ End ไม่อนุญาตรี Overworld หลักขณะเซิร์ฟเวอร์เปิดอยู่ หรือโลกที่ม็อดอื่นใช้คลาสโหลดโลกเฉพาะ เส้นทางไฟล์โลกต้องอยู่ภายใน save ไม่เป็น symbolic link และไม่ซ้อนกับไฟล์ของอีกมิติ

ก่อนถึงรอบรีอัตโนมัติ ระบบประกาศเตือนที่ 5 นาที, 3 นาที, 30 วินาที และนับถอยหลัง 10 → 1 วินาที แยกตามโลกและไม่ประกาศช่วงเดิมซ้ำในรอบเดียวกันระหว่างเซิร์ฟเวอร์รัน หากเซิร์ฟเวอร์หยุดหรือค้างข้ามช่วงเวลา จะประกาศช่วงปัจจุบันโดยไม่ไล่ส่งข้อความย้อนหลัง คำสั่งรีทันทีไม่รอช่วงแจ้งเตือน เมื่อเข้าคิวรีจะปิดการเข้าโลกนั้น งานรีหลายโลกทำทีละโลก จากนั้นย้ายผู้เล่นไปจุดกลับที่ปลอดภัยนอกโลกที่จัดการรี หรือไปจุดเกิด Overworld บันทึกผู้เล่น ถอนโลกออกจากรายการที่ tick ระบายงาน chunk ข้ามหลาย tick ก่อนปิดไฟล์และย้ายโลกเก่าเป็น backup แล้วสร้างใหม่ด้วย generator และ seed เดิม Nether เก็บไฟล์ใน `DIM-1` และ End ใน `DIM1`; การรี End เริ่มข้อมูล Ender Dragon ใหม่ด้วย

บล็อก สิ่งปลูกสร้าง กล่องเก็บของ และ entity ในโลกที่รีจะเริ่มใหม่ ของในตัวผู้เล่นยังอยู่ ผู้เล่นออฟไลน์ที่เข้ารุ่นโลกเก่าจะถูกส่งกลับเมื่อเข้าเกมหรือเกิดใหม่ ระบบเก็บประวัติรุ่นโลกไว้แม้ยกเลิกรีอัตโนมัติแล้ว เพื่อให้ยังตรวจพิกัดเก่าของผู้เล่นได้

ถ้าย้ายผู้เล่นออกไม่ได้ หรือระบาย chunk ไม่สำเร็จภายใน 60 วินาที จะหยุดรีและล็อกการเข้าโลกนั้น พร้อมบันทึกข้อผิดพลาดใน log ไม่ย้ายไฟล์โลกที่ยังเปิดอยู่ หากโลกถูกถอนจากรายการแล้วแต่รีไม่สำเร็จ จะปิดไฟล์ที่ค้างเมื่อหยุดเซิร์ฟเวอร์ ให้แก้สาเหตุก่อนรีสตาร์ต งานที่ค้างถูกบันทึกไว้และจะดำเนินต่อหลังเปิดเซิร์ฟเวอร์

## ข้อมูลและ backup

### Config ข้อความฝั่งเซิร์ฟเวอร์

หลังเปิดเซิร์ฟเวอร์ด้วยม็อดรุ่นนี้ ไฟล์จะถูกสร้างใน `<save>/serverconfig/neoworld-world-messages.toml` เป็น config แบบ SERVER ของ NeoForge แก้ข้อความในไฟล์ของ save ที่ใช้งานอยู่ คำนำหน้าจะถูกเติมให้อัตโนมัติ และ `{seconds}` ใน countdown จะถูกแทนด้วยเลข 10 ถึง 1 ตั้งข้อความใดเป็น `""` เพื่อปิดเฉพาะข้อความนั้น โดยไม่ปิดการรีโลก การกำหนดผู้รับยังเหมือนเดิม

```toml
[messages]
prefix = "[จัดการโลก] "
warning5Minutes = "โลกนี้จะรีเซ็ตในอีก 5 นาที กรุณาเก็บของและออกจากโลก"
warning3Minutes = "โลกนี้จะรีเซ็ตในอีก 3 นาที กรุณาเก็บของและออกจากโลก"
warning30Seconds = "โลกนี้จะรีเซ็ตในอีก 30 วินาที กรุณาเก็บของและออกจากโลก"
countdown = "โลกนี้จะรีเซ็ตในอีก {seconds} วินาที"
preparing = "เตรียมรีโลกนี้ กรุณาเก็บของและออกจากโลก"
starting = "กำลังรีโลกนี้ ย้ายผู้เล่นออกจากโลก"
success = "รีโลกเรียบร้อยแล้ว สามารถกลับเข้าได้"
failure = "รีโลกไม่สำเร็จ ปิดการเข้าโลกชั่วคราว กรุณาแจ้งแอดมิน"
```

- ข้อมูลระบบอยู่ใน `<save>/neoworld/world-management.json` แยกจากมิติที่รี ไม่ใช้ฐานข้อมูลรวมระหว่างเซิร์ฟเวอร์ และแทนไฟล์แบบ atomic
- เมื่อใช้ระบบใหม่ครั้งแรก จะย้ายเวลาและจุดกลับจาก `resource-world.json` เดิม หากมี โดยเก็บไฟล์เดิมไว้ หากเป็น save ใหม่ โลกทรัพยากรที่มีอยู่จะตั้งรีทุก 7 วันเป็นค่าเริ่มต้น
- โลกเก่าอยู่ข้างโฟลเดอร์มิติ เช่น `dimensions/neoworld/resource_world-backup-<timestamp>`, `DIM-1-backup-<timestamp>` หรือ `DIM1-backup-<timestamp>` ไม่มีการลบ backup อัตโนมัติ แอดมินต้องจัดการพื้นที่เก็บตามต้องการ
- การบันทึกหรือปิดไฟล์จำนวนมากอาจทำให้ tick ช้าชั่วคราว ม็อดที่เก็บข้อมูลโลกเพิ่มเติมนอกโฟลเดอร์มิติอาจต้องมีกลไกรีของตัวเอง

## การตรวจบนเซิร์ฟเวอร์ทดสอบ

ยังต้องทดสอบก่อนใช้กับ save จริง: สิทธิ์ผู้เล่นทั่วไป/แอดมิน/console, ชื่อผู้เล่นและ selector, tp และสุ่มใน Overworld/Nether/End/มิติ NeoWorld, เพิ่ม–เปลี่ยน–ยกเลิกรอบหลายโลก, รีด้วยมือโดยไม่เพิ่มรอบก่อน, รีระหว่างมีผู้เล่นและ chunk ที่โหลดอยู่, ผู้เล่นออฟไลน์กลับหลังรี, การย้ายข้อมูลระบบเดิม, และรีสตาร์ตระหว่างรี ตรวจว่าโลกรอบใหม่ไม่มีบล็อกทดสอบเดิม แต่โลกอื่นและของในตัวผู้เล่นยังอยู่

ตรวจแยกกรณีหลายโลกครบกำหนดพร้อมกัน, ไม่พบจุดกลับที่ปลอดภัย, และการเขียนข้อมูลล้มเหลว โดยต้องไม่ประกาศว่ารีสำเร็จก่อนบันทึกสถานะเสร็จ
