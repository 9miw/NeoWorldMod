# Quest Navigation Implementation Plan

**Goal:** นำทางผู้เล่นตามเส้นทางที่กำหนดไว้ ไปทำและส่งเควสต์ Custom NPCs โดยเห็นจุดแสงเฉพาะเจ้าของเควสต์

**Architecture:** Custom NPCs เป็นเจ้าของสถานะและรางวัล แอดมินวางบล็อกนำทางบนพื้นเพื่อสร้างกราฟ NeoWorld อ่านสถานะเควสต์บนเซิร์ฟเวอร์ เลือกเส้นทางจากกราฟ แล้วส่งอนุภาคเฉพาะผู้เล่น เริ่มด้วยคำสั่งติดตามหนึ่งเควสต์ ไม่เพิ่ม GUI หรือ HUD ในระยะแรก

**Tech Stack:** Java, NeoForge, Custom NPCs dependency `curse.maven:customnpcs-unofficial-1052708:7411561`.

## ขอบเขตที่ตกลง

- ติดตามครั้งละหนึ่งเควสต์ ใช้จุดเชื่อมตามถนน ประตู และบันได
- วางบล็อกนำทางบนพื้นห่างกันประมาณ 5–10 บล็อก; วางถี่กว่านี้ตรงทางเลี้ยวได้
- ตัวบล็อกมองเห็นเฉพาะ Creative ไม่มี collision และไม่กีดขวางทางเดิน; การแก้เส้นทางต้องมีสิทธิ์แอดมิน ไม่ใช่ตรวจ Creative อย่างเดียว
- เชื่อมบล็อกใกล้กันอัตโนมัติ และให้แอดมินเพิ่มหรือตัดเส้นเชื่อมเองได้
- ผูก NPC กับปลายทางตาม ID เควสต์ และรองรับพื้นที่เป้าหมายสำหรับเควสต์ล่าหรือเก็บของ
- จุดแสงโค้งนุ่มตามแนวทาง แต่ต้องย้อนกลับไปใช้แนวเส้นตรงระหว่างจุดเมื่อการโค้งตัดสิ่งกีดขวาง
- แสดงทางทีละช่วง เฉพาะผู้เล่นเจ้าของเควสต์
- เปลี่ยนปลายทางจากจุดทำภารกิจไปจุดส่งเมื่อเป้าหมายครบ
- หยุดเมื่อส่งเควสต์ ยกเลิกติดตาม หรือถึงปลายทาง; ถ้ายังทำภารกิจอยู่ ให้นำทางต่อเมื่อออกจากบริเวณปลายทาง
- ยังไม่เพิ่มลูกศร HUD ไม่วางบล็อกในแมปแทนแอดมิน และไม่มอบรางวัลเอง

## Approaches

- คำสั่งบันทึกพิกัดทีละจุด: ไม่ต้องเพิ่มบล็อก แต่จัดเส้นทางในแมปไม่สะดวก
- บล็อกกำหนดเส้นทาง: ผู้ใช้เลือกแนวทางนี้ มองตำแหน่งและปรับทางได้ใน Creative โดยตรง
- ค้นหาทางจากภูมิประเทศทั้งหมด: ซับซ้อนและคุมเส้นทางเมืองยาก จึงไม่ใช้ในรุ่นแรก

## รายละเอียดเสนอสำหรับการลงมือ

- ค่าเริ่มต้นระยะเชื่อมอัตโนมัติ 10 บล็อก โดยปรับได้; ต้องอยู่ dimension เดียวกันและตรวจทางเดิน ไม่เชื่อมเพียงเพราะระยะใกล้
- ถนนขนานหรือเส้นทางต่างระดับอาจยังเชื่อมผิดได้ จึงต้องมีโหมดดูเส้นเชื่อมและการตัดเชื่อมแบบถาวร
- เก็บกราฟและข้อยกเว้นการเชื่อมเป็นข้อมูลรายโลก ไม่สแกนบล็อกทั้งโลกทุก tick และไม่โหลด chunk ทั้งโลกเพื่อหาจุด
- การวาง/ทุบบล็อกอัปเดตกราฟ; ล้างเส้นทางที่อ้างถึงจุดที่ถูกลบ และเก็บจุดใน chunk ที่ยังไม่โหลดไว้ได้
- การผูก NPC รุ่นแรกบันทึก UUID, dimension และพิกัดที่เลือก เป็นปลายทางคงที่; NPC ที่เดินย้ายตำแหน่งต้องผูกใหม่ ไม่สัญญาว่าติดตาม NPC เคลื่อนที่
- ตรวจทางโค้งด้วยรูปร่าง collision และพื้นที่ยืน ไม่อาศัยแค่ raycast เส้นเดียว; ถ้าทางไม่ผ่านให้ไม่เชื่อม

## API ที่ตรวจจาก JAR แล้ว

- `PlayerQuestController.isQuestActive(Player, int)`
- `PlayerQuestController.isQuestCompleted(Player, int)`
- `PlayerQuestController.isQuestFinished(Player, int)`
- `PlayerData.get(Player).questData.activeQuests`
- `QuestData.isCompleted`

ต้องตรวจ bytecode ของเมธอดสถานะก่อนเลือกใช้ เพื่อยืนยันความหมายและผลข้างเคียง ไม่เรียกเมธอดที่เปลี่ยนความคืบหน้าเอง

## Task 1: ข้อมูลเส้นทางและการเลือกทาง

**Proposed files:** `navigation/NavigationGraph.java`, `navigation/NavigationSavedData.java`, `navigation/NavigationMarkerBlock.java`, `client/navigation/NavigationMarkerRenderer.java` ใต้ `src/main/java/com/ambition/neoworld/` และ regression test ของกราฟ; เพิ่มทะเบียนบล็อก/ไอเทม/renderer ตามโครงสร้างเดิม

- [ ] อ่านรูปแบบโหลด config และ regression test ที่มีอยู่เฉพาะตัวอย่างที่จำเป็น
- [ ] เพิ่มบล็อกนำทางและไอเทมสำหรับแอดมิน พร้อม resource ที่จำเป็น; ใช้ renderer แสดงเฉพาะ Creative และตรวจ dedicated server ไม่โหลดคลาส client
- [ ] เก็บข้อมูลรายโลก: จุดเชื่อมมี ID, dimension, พิกัด และเส้นเชื่อม; binding เควสต์มี quest ID, objective node, turn-in node และรัศมีถึงเป้าหมาย
- [ ] ตรวจ ID ซ้ำ จุดอ้างอิงหาย ตัวเลขผิด และเส้นเชื่อมข้าม dimension; ปฏิเสธ config ที่ผิดพร้อมข้อความระบุตำแหน่ง
- [ ] เชื่อมจุดที่ผ่านการตรวจทางเดินในระยะที่กำหนด และรองรับ forced/blocked edges ซึ่งบันทึกข้ามการเปิดโลกใหม่
- [ ] เพิ่มคำสั่งแอดมินสำหรับดูเส้นเชื่อม เพิ่ม/ตัดเส้นเชื่อม และผูก NPC หรือพื้นที่กับเควสต์ โดยตรวจสิทธิ์ฝั่งเซิร์ฟเวอร์
- [ ] หาเส้นทางสั้นสุดด้วยระยะทางเส้นเชื่อม; ตรวจการเริ่มเข้ากราฟจากตำแหน่งผู้เล่นด้วย ไม่ลากทางจากจุดใกล้ที่สุดทะลุกำแพง
- [ ] ทดสอบทางแยก กราฟไม่เชื่อม จุดเริ่มเท่าปลายทาง และข้อมูลผิด
- [ ] ทดสอบวาง/ลบจุด บันทึก/เปิดโลกใหม่ chunk unload และ blocked edge ไม่ถูกเชื่อมคืนอัตโนมัติ
- [ ] รัน regression test ที่เกี่ยวข้อง และ `.\gradlew.bat compileJava`

## Task 2: ผูกสถานะ Custom NPCs และการติดตาม

**Proposed files:** `navigation/CustomNpcQuestBridge.java`, `navigation/QuestNavigationService.java`, `command/QuestNavigationCommand.java`

- [ ] ยืนยันความหมายของเมธอดสถานะด้วย bytecode ใน dependency ที่ติดตั้ง
- [ ] เพิ่ม `/questnav track <questId>` และ `/questnav stop`; ตรวจบนเซิร์ฟเวอร์ว่าเควสต์ active และมี binding ก่อนติดตาม
- [ ] เก็บการติดตามในหน่วยความจำ ไม่เขียนทับข้อมูล Custom NPCs; ออกจากเกมแล้วล้างสถานะ
- [ ] ตรวจสถานะทุก 20 ticks; เปลี่ยนไปจุดส่งเมื่อเป้าหมายครบ และล้างเมื่อเควสต์หายหรือส่งแล้ว
- [ ] ถ้าคนละ dimension หรือไม่มีเส้นทาง ให้แจ้งผู้เล่นและไม่วาดเส้นตรงข้ามสิ่งกีดขวาง
- [ ] ทดสอบ active/completed/finished, ยกเลิกเควสต์, เปลี่ยนมิติ และสองผู้เล่นติดตามต่างกัน
- [ ] รันการทดสอบที่เกี่ยวข้อง และ `.\gradlew.bat compileJava`

## Task 3: จุดแสงเฉพาะผู้เล่น

**Proposed file:** `navigation/NavigationTrail.java`; ใช้ event registration ตามรูปแบบเดิมที่ตรวจพบตอนลงมือ

- [ ] ส่งอนุภาคจากเซิร์ฟเวอร์ถึงผู้เล่นรายคน ไม่ broadcast
- [ ] แสดงเฉพาะช่วงใกล้ตัวไม่เกิน 24 บล็อก เว้นจุดประมาณ 1 บล็อก อัปเดตทุก 10 ticks และจำกัดจำนวนอนุภาคต่อรอบ
- [ ] สร้างแนวโค้งผ่านจุดนำทาง และใช้แนวตามเส้นเชื่อมเดิมเมื่อโค้งชนสิ่งกีดขวาง; คงความสูงตามทางเดินตรงบันได
- [ ] คำนวณเส้นทางใหม่เมื่อเดินออกห่างจากเส้นเดิม โดยมี cooldown; ใช้เส้นเชื่อมที่กำหนดไว้เท่านั้น
- [ ] ทดสอบจริงด้วยเควสต์หนึ่งรายการ: รับ → เดินไปทำ → ทำครบ → กลับส่ง และผู้เล่นอีกคนต้องไม่เห็นจุดแสง
- [ ] ตรวจทางโค้ง ประตู บันได การถึงปลายทาง และการเดินหลุดเส้นทาง
- [ ] รัน `.\gradlew.bat compileJava`; รายงานแยกผลคอมไพล์กับการทดสอบในเกม

## ข้อมูลที่ต้องมีก่อนทดสอบในแมปจริง

ID เควสต์แรก, dimension และ NPC/พื้นที่เป้าหมาย โดยแอดมินวางบล็อกตามทางเดินจริงและผูกปลายทางในเกมได้ ไม่จำเป็นต้องส่งพิกัดให้ผู้พัฒนาเพื่อสร้างระบบพื้นฐาน ห้ามเดาพิกัดหรืออ้างว่าทดสอบในเกมแล้วเมื่อยังไม่มีข้อมูลนี้
