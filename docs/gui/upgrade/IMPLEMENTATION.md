# แก้ขอบทองแดงบิดเบี้ยว

สกรีนช็อตผู้ใช้พบหมุดเป็นวงรี ลายข้างยาว ลายพื้นใหญ่ และปุ่มแบน UpgradeScreen ใช้พื้นที่ลายที่วัดใหญ่ขึ้น (ขอบนอก 80/มุม 10; แผง 48/6; ปุ่ม 48/6; หัว 60/8) จำกัดขอบต้นทาง X/Y แยกและใช้สเกลมุมร่วม แถบตรงปูซ้ำสเกลเดียวแทนยืด พื้นรองปู patch จัตุรัส ทุกสถานะปุ่มคงรูปเดิมและขอบคลิกเดิม ไม่เปลี่ยนช่องไอเทมหรือกฎเกมเพลย์

ภาพประกอบแอสเซ็ตออฟไลน์ `navy_copper/slice-fix-preview.png` วาดตามเรขาคณิตเชิงตรรกะเดิมแล้วขยาย nearest 3x เป็นตรวจการสุ่ม PNG จริง ไม่ใช่ภาพเกม compileJava ผ่าน ยังต้องมีภาพในเกมและ GUI Scale ที่ทราบเพื่อเทียบรันไทม์ที่แก้กับม็อกอัป

# แอนิเมชันคลิกตีอัปเกรด

UpgradeScreen แสดงประกายทองแดงวิ่งจากช่องวัตถุดิบที่ส่งไปช่องอุปกรณ์ วงโคจรเต้นอย่างน้อย 1000ms และเอฟเฟกต์ผล 850ms จับ mask ช่องต้นทางก่อนใช้วัตถุดิบ เฉพาะคำตอบเซิร์ฟเวอร์เผยสำเร็จ/ล้มเหลว การเปลี่ยนรีวิชันอินพุตอย่างเดียวไม่แสดงผล เมนูซิงก์ ContainerData ฟิลด์ที่หก เป็นลำดับผล 16 บิตรวมผลซ้ำ อัปเดตหลัง code/level/outcome ผล 4 หมายถึงป้องกันการสุ่มลดขั้น/รีเซ็ตโดยเฉพาะ สุ่มไม่เปลี่ยนธรรมดาไม่แสดงโล่ผิด คงกฎ/ต้นทุนบริการ ทั้งไคลเอนต์/เซิร์ฟเวอร์ต้องใช้ม็อดใหม่

สำเร็จ: แฟลชอำพันและประกายรัศมี ไม่เปลี่ยน: ควันจาง ลดขั้น/รีเซ็ต: แฟลชแดงและรอยแตกชั่วคราว ล้มเหลวที่ป้องกัน: ไอคอนโล่ทองแดงเดิม เสียงใช้ Vanilla anvil/level-up/shield ไม่เพิ่มแอสเซ็ต ปุ่มแสดงกดสั้นแล้วล็อกช่วงเตรียมและเผยผล เมินคลิกช่องระหว่างแอนิเมชันท้องถิ่น แต่ Escape/ปิดยังคืนอินพุตจริงตามปกติ หากไม่มีคำตอบหมดเวลาห้าวินาทีพร้อมข้อความกลาง ไม่แต่งผลสุ่ม เอฟเฟกต์ชั่วคราวจบเมื่อปิด ไม่ทิ้งอนุภาคถาวรหรือเปลี่ยนไอเทมโลก สแต็กจริง ยอดเงิน และสถิติอาจซิงก์ก่อนภาพเผยผล

ตรวจสอบ: compileJava ผ่าน เสียง การเห็นอนุภาค ซิงก์ผลซ้ำ ย่อขยาย GUI และเวลาบนไคลเอนต์จริงยังไม่ยืนยันในเกม

# Navy / Copper A — สกินรันไทม์ปัจจุบัน

ภาพอนุมัติ `navy_copper/approved-mockup.png` ผู้ใช้เลือก A และขอเชื่อม `UpgradeScreen` อ้าง PNG ตรงใน `assets/neoworld/textures/gui/upgrade/navy_copper/`: กรอบนอก/แผง หัว/หัวส่วน ช่องอุปกรณ์/คลัง ปุ่มหลักสี่สถานะ พื้นปิด ราง/ไส้คืบหน้า และไอคอนตกแต่งหกตัว เลย์เอาต์เงินด้านล่างเป็นประวัติ

ขนาดเชิงตรรกะเดิม 360x232 วาดกรอบนอกครั้งเดียว แผงในสี่ชิ้นไม่ทับกันที่ (8,28,166,109), (178,28,174,109), (8,139,166,89), (178,139,174,89) ภาพต้นทางมี padding โปร่งใส 2px ตัดออกเมื่อวาดและ nine-slice ขอบทองแดงที่วัด ข้อความ ค่า และสแต็กไดนามิก ปุ่มสี่สถานะใช้ขอบต้นทาง 348x128 ร่วมและกรอบคลิกเดียว (18,208,144,16) กดเมาส์/Enter/Space ใช้สกินกด ปิดใช้สีเทา ปิดมีพื้นแยกและ X ไดนามิก

ช่องอุปกรณ์ (28,54) วัตถุดิบ (30,94), (82,94), (134,94) คลัง 9x3 จาก (185,151) ฮอตบาร์ y207 ระยะ 18 ไอเทม Vanilla และอินพุตคงสเกลเดิม ต้นทุน เปอร์เซ็นต์สำเร็จสุดท้ายค่าเดียว และแถบอำพันซ้ายล่างตาม A ชี้ดูยอดเงินแน่นอนและข้อมูลรวมโบนัสได้ ปุ่มหลักอธิบายการใช้ของเสริม กฎผลและตรวจเซิร์ฟเวอร์เดิมไม่เปลี่ยน

ตรวจสอบ: คอมไพล์ Java และตรวจขนาด/อ้างเท็กซ์เจอร์ผ่าน หน้าต่าง 1280x720 GUI Scale 3 มีวิวพอร์ต 427x240 รองรับ 360x232 ถ้าบังคับสเกลให้วิวพอร์ตเล็กกว่าอาจตัด ไม่มีภาพเกมจริงหรือการวัด GUI Scale ปัจจุบัน ยังไม่ยืนยันสัดส่วนอนุมัติ ความอ่านง่ายไทย การสุ่มมุม ชี้/อินพุต และภาพใน GUI Scale ที่รองรับ คอนเซปต์สร้างไม่ใช่สกรีนช็อตระบบนี้

## บันทึกระบบเดิม

# เมนูโต๊ะแบบ A

คลิกขวา `neoworld:upgrade_table` เปิด `UpgradeMenu` และ `UpgradeScreen` ผู้เล่นวางไอเทมจริงสี่ช่อง: อุปกรณ์ หิน ป้องกันรวมเสริม และ booster เสริม อินพุต 1..3 ที่ x=24/62/100, y=94 ป้องกันคงเลเวลทุกผลล้มเหลว booster เพิ่มสิบจุดเปอร์เซ็นต์ สำเร็จสุดท้ายไม่เกิน 100 ของเสริมที่เลือกแต่ละอย่างใช้หนึ่งชิ้นต่อความพยายามที่ยอมรับ เมนูใช้ช่อง/เคอร์เซอร์/ลาก/shift-click Vanilla การปิด หลุด หรือโต๊ะใช้ไม่ได้ เรียก `clearContainer` Vanilla เพื่อคืนคลังหรือทิ้งเมื่อจำเป็น ไม่มีสำเนาพรีวิวที่หยิบได้ คลังผู้เล่นคง 27 ช่องและฮอตบาร์ 9

หน้าจอใช้กรอบและช่องว่างส่งออก `NeoButton`, `NeoProgressBar` ซ้ำ ชื่อ แถวสถิติ ต้นทุน ยอดเงิน ไอคอน โอกาส เตือน ผล และป้ายไดนามิก แสดงเฉพาะเปอร์เซ็นต์สำเร็จ พรีวิวตามสูตรโบนัสปัจจุบัน ไม่รวมเอนชานต์ เอฟเฟกต์ผู้เล่น และดาเมจเฉพาะสไตล์ ระบุ Impact/Stun Armor เป็นโบนัสอัปเกรด ไม่บวกแถวดาเมจโบนัสอธิบายซ้ำเข้ารวม

ขนาดเชิงตรรกะปัจจุบัน 320x232 ไม่สเกลทั้งจอ ไม่ใช้ขนาดจอเสมือนหรือแปลงพิกัดเมาส์ ไอคอน/ข้อความใช้ GUI Scale Minecraft ปกติ คลังระยะ 18 ไอคอน 16x16 ช่องตกแต่ง 18x18 ตามสัดส่วน Vanilla ช่องอินพุตทั้งสามก็ใช้กรอบ 18x18 รอบช่องเดิม `UpgradeMenu` กำหนดค่ากว้าง/สูงและกริดร่วม ส่วนบน/ล่างกรอบว่างปรับขนาดแยกให้คลังสูงพอ `layout.json` เก่าและภาพตรวจส่งออกอธิบายการเตรียม 512x400 ก่อนหน้า ไม่ใช่พิกัดปัจจุบัน ยังรอตรวจเลย์เอาต์แก้ในเกม

พิกัดช่องผู้เล่นปัจจุบัน: คลังเริ่ม (147,151) สามแถวระยะ 18 ฮอตบาร์ y=207 อินพุต (62,56), (36,94), (94,94) สถิติเป็นตารางก่อน/หลัง/เพิ่ม รูปแบบตัวเลขกระชับและฟอนต์เดิม ราคา Silver แต้มล้มเหลว ผล และปุ่มอยู่ซ้ายล่าง ชี้ดู Silver แน่นอนได้เมื่อป้ายถูกตัด เคารพ GUI Scale Minecraft จอเล็กผิดปกติหรือสเกลบังคับต่ำกว่า 320x232 อาจตัดเมนูแทนย่อไอคอน

แบบอนุมัติล่าสุด `04-approved-single-frame.png` รันไทม์วาด `upgrade_single_frame.png` ครั้งเดียวเต็ม 320x232 มีเฉพาะขอบนอกเงิน/ทองและพื้นชาร์โคล โค้ดวาดเส้นแบ่งตั้งหนึ่ง นอนหนึ่ง หัว และเนื้อหา ไม่ซ้อนกรอบแผงในหรือแผ่นหัว `tools/prepare_upgrade_single_frame.py` ส่งออก nearest-neighbor พร้อมเมทาดาทา และตรวจกรอบช่อง 36 อยู่ขวาล่าง มีที่ใต้ฮอตบาร์แปดหน่วย `06-single-frame-layout-check.png` ตรวจประกอบแอสเซ็ต ไม่ใช่ภาพเกม `single-frame-layout.json` บันทึกเรขาคณิตปัจจุบัน แทนกรอบเก่าแบ่งบน/ล่างที่กล่าวก่อนหน้า

`UpgradeSubmitPayload` ส่งเฉพาะ container ID เมนู token เซสชันสุ่มต่อการเปิด และรีวิชันพรีวิว เซิร์ฟเวอร์หาผู้เล่นจากคอนเท็กซ์ ตรวจเมนู เจ้าของ บล็อกโต๊ะยังอยู่ รัศมีแปดบล็อก มีชีวิต/ผู้ชม สแนปช็อตเอสโครว์ปัจจุบัน เคอร์เซอร์ว่าง และคูลดาวน์ห้าทิก แก้อินพุตหรือพยายามที่รับ/ปฏิเสธเพิ่มรีวิชันเพื่อปฏิเสธซ้ำ/เก่า คำนวณต้นทุน สุ่ม และยอดใหม่ฝั่งเซิร์ฟเวอร์ ไคลเอนต์ส่งค่าเหล่านี้ไม่ได้ ไคลเอนต์ล็อกปุ่มรอรีวิชันเปลี่ยนและมีหมดเวลาสำหรับคำขอถูกปฏิเสธ

บริการใช้ธุรกรรมร่วมระหว่างทางเข้าคลังผู้เล่นเดิมกับคอนเทนเนอร์เอสโครว์เมนู เตรียมสำเนาไอเทมใหม่ก่อนหัก Silver ความพยายามที่รับทุกครั้งใช้สกรอลล์ที่เลือกรวมสำเร็จ และหิน/Silver ซิงก์เมนู Vanilla อัปเดตสแต็กอินพุต รีวิชัน/ผล เพย์โหลดเศรษฐกิจเดิมอัปเดต Silver รีวิชันใช้สองฟิลด์ 16 บิตเลี่ยง container data ถูกตัด ไม่มีที่เก็บถาวรโต๊ะเพิ่ม

โปรโตคอลเป็น 14 ทั้งคู่ต้องม็อดตรงรุ่น รีเกรสชัน packet codec ครอบคลุม container ID ขอบค่าสุดขั้วเซสชัน signed 64 บิตและรีวิชัน signed 32 บิต และปฏิเสธข้อมูลขาด รีเกรสชันผล/โบนัสเดิมผ่านด้วย ต้องตรวจ `compileJava`, `processResources` การใช้เมนูในเกม shift-click/ลาก/ฮอตบาร์ ปิดคลังเต็ม หลุด/ตาย ถอดโต๊ะ/ระยะ การแยกหลายคน จ่ายครั้งเดียว โหลด dedicated server และเทียบแบบ A ยังไม่ยืนยัน
