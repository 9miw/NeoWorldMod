# การจัดเนื้อหาห้องรอ

อ้างอิง `waiting-room-v2-approved.png` โดยคงกรอบ V5 ที่กว้างกว่า

`DungeonWaitingContentLayout` วัดเมทาดาทา หัวตารางสมาชิก สามแถวสมาชิก สรุปพร้อม และแถบรางวัลเป็นเลย์เอาต์เดียว แบบกะทัดรัดต้องการ 220 หน่วย GUI เดิม แบบโปร่ง 280 วิวพอร์ตเชิงตรรกะ 640x360 ขึ้นไปเนื้อหาพอดีโดยไม่เลื่อนตัวหน้า วิวพอร์ตเล็ก เช่น 426x240 ที่หน้าต่าง 1280x720 อาจใช้เมื่อ GUI Scale 3 ยังคงเลื่อนแนวตั้งแทนบีบข้อความหรือซ่อนตัวควบคุม ความละเอียดหน้าต่างจริงอย่างเดียวไม่ได้ตัดสินว่าเนื้อหาพอดีหรือไม่

แถวสมาชิกสูง 18/22 หน่วย แสดงสกินจริงและเลเวล/ความพร้อมจากเซิร์ฟเวอร์ เกินสามคนเลื่อนแยก หัวคอลัมน์ไม่ทับแถวแรก ช่องรางวัล 20/24 หน่วยและเลื่อนแนวนอนเมื่อล้น ท้ายคงที่อยู่นอกกรอบตัดและพื้นที่เลื่อนทั้งหมด

ภาพทางเข้าและดาบไขว้ปุ่มเริ่มแทนสัญลักษณ์กุญแจกลาง วาดไอคอนเริ่มเฉพาะเมื่อไอคอนกับข้อความพอดีโดยไม่ซ้อน ไม่เปลี่ยนพฤติกรรมพร้อม เริ่ม ออก ยุบ ปาร์ตี้ หรือเครือข่าย

## ปุ่มท้ายตามบทบาท

`DungeonRoomActions` ควบคุมการแสดงการกระทำเดิม:
เจ้าของทีมเห็นจัดการปาร์ตี้ ยุบพร้อมยืนยัน และเริ่ม สมาชิกทั่วไปเห็นพร้อม/ยกเลิกพร้อมและออก เจ้าของโซโลเห็นเริ่มและออก ผู้ไม่ใช่สมาชิกไม่เห็นการกระทำ ปุ่มที่รอคำตอบหรือไม่ใช่สถานะรอยังปิดใช้
จัดการปาร์ตี้เปิด PartyScreenController เดิมโดยไม่ออกห้องดันเจี้ยน ระบบเดิมยังตรวจสิทธิ์ปาร์ตี้ X อยู่นอกกรอบขวา ฮิตบ็อกซ์เห็นครบ 18x18 และปิดเฉพาะจอ ไม่ออกห้อง

คอมไพล์และรีเกรสชันเรขาคณิตตรวจวิวพอร์ตเชิงตรรกะที่รองรับ นี่เป็นการแก้โค้ด/เลย์เอาต์ ยังไม่ใช่ยืนยันภาพตรงในเกม
